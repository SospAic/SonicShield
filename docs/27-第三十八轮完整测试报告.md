## 三、本轮实测踩出来的四个坑（都会造成假红/假绿）

### 🔴 P1-1 · 「禁用」断言在空态是**假红**

**症状**：首版 MV-01 断言 `onPressed == null`，实测 `Found 0 widgets with text "未选择设备"`。

**真因**：`multi_video_screen.dart` 的 `build` 在 `sessions.isEmpty` 时**早返回**空态分支，
**`_CommandBar` 整块不构建** —— 它不是"渲染成禁用"，而是**根本不存在**。

**修法**：断言改为"指令条不存在"（`findsNothing`），并**另加一例**
（MV-01b）用注入缝打到 `_CommandBar(session: null)` 那个**真正存在的**防御分支。

**教训（可复用）**：**"不可用"有两种形态 —— `onPressed == null`（禁用）与"不构建"。
断言必须对准其中真实的那一种，否则是假红。**

### 🟡 P1-2 · `showDialog` 取消路径必须推完转场动画

点遮罩后 `SimpleDialog` **会留在树上直到转场结束**。实测只 `pump` 60ms ⇒ 假红"对话框还在"。
修法：`pump()` + `pump(500ms)` 再断言。

### 🟡 P1-3 · `prefer_conditional_assignment` 会盯上注入缝

`if (activeId != null) { _activeId = activeId; } else if (_activeId == null) { … }`
被 lint 判红 ⇒ **门禁第 1 步红**。修法：`_activeId = activeId ?? _activeId;`
再 `_activeId ??= …;`（语义等价、写法合规）。

### 🟡 P1-4 · 注入缝自身会**抬分母**

可测面 `LF` 9562 → **9576（+14）** —— 那是新增代码的**可执行行**。
**如实计入分母**（分母涨 ⇒ 比率被稀释）。这正说明 `MIN_COVERED`（**分子绝对地板**）
是不可省的最后防线；**绝不许**把这 14 行塞进设备层豁免名单来美化比率。

## 七、本轮沉淀的可复用方法（已写进 `docs/17 §69.4`）

1. **★ 目标选择法则**：缺口降序看 TOP 时，**先看缺口是否同源** ——
   **同源的 100 行 < 异源的 500 行**。判据：缺口是否全落在同一个 `if`/早返回分支之后。
2. **★ `@visibleForTesting` 注入缝五步检查清单**：
   ① 只加方法、不改既有签名/行为；② 确认 `invalid_use_of_visible_for_testing_member`
   是否设为 `error`；③ **逐条 grep `test/` 里读该文件源码文本的锁**，确认新方法**不落在
   被切的函数体切片里**；④ 缝要自清但**绝不关 `StreamController`**（关了后续用例全假绿）；
   ⑤ 缝自身抬分母，**如实计入**。
3. **★ 空态断言必须区分「禁用」与「不构建」**（见 P1-1）。
4. **★ 中断自恢复判据**：只看 `_pt/` 产物与 `.done` **是否成对** ——
   成对即"上一轮跑完了"（本轮开场即据此判定**无需续跑、从头推进**）；
   缺失即"作业从没跑过"，要去**定位挂死**（第三十七轮的教训）。
5. **中继纪律**：`job.txt` 单槽 + `IgnoreNew` ⇒ 触发前后核对 `State` 与产物；
   每条命令必带 **`timeout <秒>` 硬上界**；新建中继脚本换命名空间
   （`jobK*` / `jobL1..L11` / **`jobM1..M4` 本轮已占**）。
