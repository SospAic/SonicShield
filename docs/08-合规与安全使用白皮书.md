# 08 · 合规与安全使用白皮书

> 本文档是产品的法律边界声明与合规设计说明。**它不是法律意见书**；
> 具体个案请咨询当地执业律师。

---

## 1. 产品的合法用途（Whitelist）

- 定时/随机提醒：久坐、喝水、服药、习惯养成；
- 助眠/专注音：随机间隔与随机音量的白噪音、舒缓提示；
- **噪声取证**：对持续性噪声骚扰进行本地录音留证与事件日志，
  用于后续沟通、物业/居委会调解、12345 投诉、报警或司法程序；
- 守护提示：独居家人的定时确认播报。

## 2. 明确禁止的用途（Redline）

1. **利用随机播放/随机音量/自动喊话功能骚扰、恐吓、报复任何他人**；
2. 在夜间（默认 22:00–07:00 免打扰时段）或任何时段制造干扰他人的噪声；
3. 录音取证用于侵犯他人隐私（如偷录私密场所对话）而非自我保护留证；
4. **利用持续振动/随机振动功能对他人实施骚扰**（如把设备放在他人住处、
   工作台、交通工具上持续振动制造困扰），或**以振动方式损坏他人设备**；
5. 试图绕过应用内护栏（夜间独立豁免、勿扰约束、远程侧护栏）以达成上述任一目的；
6. 任何违反使用者所在地法律法规的用途。

> ⚠️ 第 4、5 条随 v1.9.0-alpha「振动能力 + 夜间独立豁免」新增。
> 振动同样是**对物理世界的输出**，与扬声器同级看待：**它的默认状态是受约束的**。

## 3. 主要法律风险提示（中国大陆为例）

| 行为 | 可能触碰的法律 |
|---|---|
| 随机时间大音量播放声音干扰邻居/他人正常生活 | 《治安管理处罚法》第 58 条（噪声干扰他人正常生活可处警告或罚款）；《噪声污染防治法》（社会生活噪声） |
| 夜间噪声扰民 | 同上，且从重情节 |
| 以喊话、恐吓音效威胁他人 | 《治安管理处罚法》第 42 条（写恐吓信或者以其他方法威胁他人人身安全）；情节严重可能涉刑 |
| 对他人正常生活造成持续干扰 | 《民法典》第 288 条起相邻关系条款（不动产相邻权利人应按有利生产、方便生活、团结互助、公平合理原则处理相邻关系）、第 1032 条起隐私权 |
| 在他人住宅/工作场所安装本应用设备进行干扰或窃录 | 可能构成非法侵入住宅、侵犯公民个人信息等 |

**正确姿势**：遭遇骚扰/噪声侵害时，优先选择**取证 → 沟通 → 投诉
（物业/12345/城管）→ 报警 → 诉讼**的合法路径；本应用的取证与日志功能
正是为此设计，而不是用于"以噪制噪"。

> 其他司法辖区（欧美、日韩等）对噪声滋扰（noise nuisance/disturbing the
> peace）、骚扰（harassment）同样有行政处罚或刑事责任，结论一致。

## 4. 应用内合规护栏（工程设计，不可绕过）

| 护栏 | 实现位置 | 说明 |
|---|---|---|
| 合规门 | `permission_flow.showComplianceGateOnce` | 首次启动强制阅读《合规使用须知》，不同意则引擎不可用（持久化标志） |
| 强制免打扰时段 | `ComplianceGuardrails.defaultQuietStart/EndHour` + `ScheduleEngine._applyQuiet` | 默认 22:00–07:00，UI 只能调窄（22–23 点开始 / 5–9 点结束）；物化期与执行期双重生效。**v79**：用户可经「夜间独立豁免」主开关（批量默认值）+ 任务级三态**双向覆盖**在该时段显式豁免，**全部留痕、远程不可开启**（见 §4.2） |
| 全局执行总开关 | `RunMasterMode`（`lib/domain/scheduling/run_pause.dart`）+ `BackgroundEngine.pausedAt()` | **v79 新增**：法定休息日（含普通周末）前一天 20:00 → 最后一天 21:00 之间默认暂停全部任务执行（跳过 + 留痕），出窗自动恢复；任务级 `forceRun` 可例外。**这是用户给自己的整体刹车（更保守），允许远程切换**（`RcCmd.runMasterSet`，须 `script` 权限位） |
| 最小冷却 | `ComplianceGuardrails.minCooldownSeconds = 60` | 编译期常量；物化去尾 + 执行期校验 |
| 音量上限 | `ComplianceGuardrails.maxMediaVolumePercent = 100` | 物化期裁剪 |
| 补执行限流 | `SchedulerConfig.catchUpLimit = 3`、逾期 10 分钟丢弃 | 防休眠唤醒后连响轰炸 |
| 全量审计 | exec_logs | 每次执行（含 skipped/failed）留痕，时间/来源/音量/时长可回溯 |
| 隐私默认 | 无 INTERNET 权限；麦克风数据不落盘 | 物理上无法外传 |

### 4.1 振动能力的补充护栏（v1.9.0-alpha）

振动是**对物理世界的输出**，与扬声器同级。用户已拍板「持续振动本地不设硬上限」，
代价用以下四条**不可裁剪**的工程约束补上（docs/20 §7.2）：

| 编号 | 约束 | 实现 |
|---|---|---|
| **S1** | **进程死即停** | 振动只由**引擎 isolate 内的 `VibrateSession`** 下发；主 isolate 崩溃/被杀 ⇒ 不再续发 |
| **S2** | **重启绝不续发** | 启动时 `stopAll()` 清残留 + 审计；**旧残留不会复活**（`VS-12` 锁定） |
| **S3** | **全局停止** | `RcCmd.vibrateStop` + 本地停止按钮，任何时刻一条命令即停（幂等） |
| **S4** | **低电量降级** | **启动闸 + 在跑检查**双点校验：跑到一半掉到阈值以下也立即停（`VS-14`） |

> ⚠️ 远程侧另有三条硬约束：
> ① 入站 `respectDnd` **强制 `true`**（`TaskWire` 与 `RcStep` 两条路径都夹紧，
> 对端不得用远程命令绕过本机勿扰护栏），被改写时**写审计**（`inboundDndDowngrade`），不静默；
> ② 传输层时长上限（`TaskWire.maxVibrateDurationSec`）是**安全边界**，
> 与"本地不设上限"不矛盾 —— 入站数据不可信；
> ③ 指令组振动步**绝不退回固定节奏**（缺处理器即 `skipped` + 审计，`RV-15` 穷举锁定）。

### 4.2 夜间独立豁免的护栏（v1.9.0-alpha；v79 语义改造）

D4 决策**削弱了既有护栏**（强制免打扰时段），因此必须用工程手段把风险收回来。
**v79 把"双钥匙（AND）"改为"主开关 = 全量默认值 + 任务级三态双向覆盖"**
（`exempt = taskExemptOverride ?? allowQuietExempt`），护栏随之调整如下：

| 约束 | 实现 | 锁 |
|---|---|---|
| **主开关即默认值** | prefs 主开关 `quietExemptMaster`；任务级 `quiet_exempt` **三态**（`null`=跟随 / `true`=强制豁免 / `false`=强制不豁免）**双向覆盖** | `QE-01` / `QE-02` / `QE-03` / `QE-06` / `QE-07` / `QE-08` |
| **默认关** | 主开关缺失/空值一律读作 `false`（未授权 ≠ 已授权）；新建任务默认 `null` 跟随 | `QE-20` / `QE-21` |
| **远程不可开启（也不可写主开关）** | `TaskWire.fromWire` **显式丢弃**入站 `quietExempt`（一律置 `null`）；远程写不到 `quiet_exempt_master`（源码扫描锁） | `QE-10` / `QE-12` / `QE-13` / `QE-14` / `QE-15` / `QE-21` |
| **写入口唯一** | 主开关写入口只允许出现在设置页（源码扫描锁） | `QE-13` / `QE-14` |
| **例外可见可回溯** | 设置页主开关下方「例外清单」只列**偏离当前主开关**的任务 | `SET-05f` |
| **全量留痕** | 每次豁免执行写审计，条目标记 `quietExempted`；`countQuietExemptSince` 可统计 | `QE-03` / `QE-25` |
| **撤销即清** | `commitAll` 是 `ignore` 幂等语义 ⇒ 撤销主开关必须 `deletePendingQuietExempt()`（**但保留** `quietExempt == true` 的强制豁免例外） | `QE-24` |
| **不随备份外流** | 任务备份导出/导入**不携带** `quietExempt` | `QE-15` |
| **窗口不可整体关掉** | `normalizeQuietWindow` 对越界/缺失/`start==end` 一律**回落合规默认**（不是夹到边界） | `QE-31` / `QE-32` |

### 4.3 全局执行总开关的护栏（v79）

**§4.2 的红线是"远程不得开启夜间豁免"（绕过免打扰护栏）；§4.3 的总开关相反 —— 它是更保守的
"整体刹车"，因此允许远程切换**（`RcCmd.runMasterSet`，`script` 权限位）：

| 约束 | 实现 |
|---|---|
| **默认 auto** | 缺失/空值/读不懂一律 `auto`（`RunMasterMode.parse` 容错）⇒ 窗口内暂停、出窗自动恢复 |
| **仅约束任务执行** | 只拦 `executeDue`（计划触发）与 `admitExecution`（声音触发 / 远程 `task.runNow`）；**非任务类显式指令（sound/script/vibrate/ptt/通话）不受影响** |
| **跳过必留痕** | 每次被拦写 `action:'runPause'` / `status:'skipped'` 审计，不静默 |
| **例外可控** | 任务级 `forceRun`（默认 false）可强制例外；远程模式**不得**授予该例外 |
| **与夜间豁免独立** | 两个开关**互不覆盖、互不改写**（不同 prefs 键、不同判据） |
| **入口在守护首页（v82 起）** | 总开关卡片 + 例外清单位于**守护首页**（`guard_screen.dart::_buildRunMasterCard`；v79 原在设置页，v82 移植）；例外清单**默认只展示 5 条**，超出折叠可展开 —— ⚠️ 与本页 §4.2「夜间豁免主开关**写入口唯一 = 设置页**」（`QE-14` 源码扫描锁）**互不影响**：`QE-14` 只扫 `quietExemptMaster` 的写入口，**不含** `runMasterMode` |

## 5. 应用商店政策

| 事项 | 结论 |
|---|---|
| `SCHEDULE_EXACT_ALARM` | 通用特殊权限，应用内引导用户授权；需在商店说明用途（"精确执行用户设定的提醒"） |
| `USE_EXACT_ALARM` | Play 政策仅限闹钟/日历核心功能应用；**本应用不使用**，避免审核风险 |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | Play 政策要求"用户显式操作 + 核心功能必要"；应用内为按钮主动申请（引导页），并说明后果 |
| 后台麦克风（iOS） | 用途字符串具体化；守卫模式提供明确的用户开关 |
| "骚扰反击"类描述 | **上架文案严禁出现"反击/报复/整蛊他人"等表述**；统一使用"提醒/取证/守护"话术 |

## 6. 数据与隐私合规

- 处理原则：最小必要（麦克风音频仅瞬时计算能量）、目的限定
  （本地检测与取证）、存储限定（应用私有目录）；
- 对照《个人信息保护法》：麦克风属敏感个人信息，应用通过
  运行时权限 + 首启告知 + 状态栏系统提示满足告知同意要求；
- 取证文件含他人声音的，使用者应仅将其用于合法维权目的并妥善保管，
  不得公开传播（可能侵犯他人肖像/声音权益或构成侮辱诽谤）；
- v1 无网络能力，天然满足"本地化存储"。
