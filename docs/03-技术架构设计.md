# 03 · 技术架构设计

> 本文档记录整体架构、关键技术决策（ADR）与平台差异处理。

---

## 1. 总体架构

```
┌─────────────────────────────────────────────────────────────────┐
│  UI 层（lib/features）                                           │
│  守护仪表盘 · 任务管理 · 音源库 · 声音守卫 · 日志 · 设置          │
│  Riverpod 状态持有 / go_router 导航 / Material 3                 │
└───────────────┬─────────────────────────────────────────────────┘
                │ providers（FutureProvider/StreamProvider）
┌───────────────▼─────────────────────────────────────────────────┐
│  服务层（lib/services）                                          │
│  PlaybackService   播放内核封装（just_audio + audio_session）     │
│  SoundGuardService 麦克风采流 → RMS → 阈值事件（record）          │
│  NotificationService / PowerService / NativeBridge / 权限流程     │
├─────────────────────────────────────────────────────────────────┤
│  后台引擎 background_engine.dart                                 │
│  运行于 flutter_background_service 前台服务隔离（独立 Dart isolate）│
│  双通道触发汇合点：Timer tick(通道A) + 原生闹钟 kick(通道B)        │
│  replan() 计划滚动 · executeDue() 幂等执行 · runAction() 动作分派  │
└───────────────┬─────────────────────────────────────────────────┘
                │
┌───────────────▼───────────────────┐  ┌──────────────────────────┐
│  领域层（lib/domain，纯 Dart）      │  │  数据层（lib/data）        │
│  TriggerConfig/ActionConfig(Task)  │  │  AppDatabase(sqflite)     │
│  ScheduleEngine.materialize()      │  │  Task/Asset/Occurrence/Log│
│  确定性随机 utils/random.dart      │  │  Repository               │
│  零 Flutter 依赖 → 可完全单测      │  │  JSON 配置列 + 索引列      │
└───────────────────────────────────┘  └──────────────────────────┘
                │
┌───────────────▼─────────────────────────────────────────────────┐
│  平台层（android/ ios/）                                          │
│  Android: MainActivity(原生桥) · AlarmWatchdogReceiver · BootReceiver│
│           ForegroundService(mediaPlayback|microphone|dataSync)    │
│  iOS:     Info.plist 后台模式(audio/processing/fetch) + BGTask    │
└─────────────────────────────────────────────────────────────────┘
```

**分层原则**

1. 领域层零 Flutter 依赖：调度引擎是纯函数，TDD 成本最低；
2. 引擎状态机以数据库（occurrences 表）为唯一事实源，双通道入口天然幂等；
3. UI 不直接触碰平台通道，全部经 services 封装。

## 2. 关键技术决策（ADR 摘要）

### ADR-001 跨平台框架：Flutter ✅

| 候选 | 评价 | 结论 |
|---|---|---|
| Flutter 3.x | 双端 UI 一致；后台能力靠插件+原生桥补齐；生态成熟；Dart 隔离模型适合常驻引擎 | **采用** |
| React Native | 后台任务生态碎片化；音频低延迟链路弱 | 否 |
| KMP | Android 端强，iOS 后台音频仍需 Swift；双份 UI 工作量 | 否 |
| 原生双端 | 保活最可控，但双倍成本 | 作为 v3 保活引擎下沉的备选 |

### ADR-002 状态管理：Riverpod ✅

编译期安全、无 BuildContext 侵入、测试友好。备选 Bloc（模板代码多）、
Provider（作者已停止演进）。

### ADR-003 数据库：sqflite（手写 SQL）✅ / Drift（迁移路径）

选择 sqflite：零代码生成（仓库无需 build_runner 即可静态分析与测试）、
稳定生态。复杂配置以 JSON 列存储，核心查询列强类型+索引。
Drift（编译期类型安全）记录为 v2 迁移路径（docs/07 §6）。

### ADR-004 调度架构：进程内引擎 + 原生精确闹钟双通道 ✅

- 通道A：引擎隔离内 Timer 周期 tick（15s）+ 到点即时执行——应用存活时亚秒级精度；
- 通道B：AlarmManager `setExactAndAllowWhileIdle` 精确闹钟看门狗——
  Doze/进程被杀/重启后拉起前台服务补执行；
- 汇合：occurrences 表状态机（pending → done/failed/skipped），
  补执行上限 catchUpLimit=3、逾期 10 分钟以上丢弃（防休眠唤醒连响）。

否决的备选：WorkManager（周期≥15min，精度不足）、
android_alarm_manager_plus（已停止维护）、纯 Dart Timer（Doze 冻结）。

### ADR-005 随机化：确定性种子（DPRNG）✅

seed = FNV-1a(hash(taskId, 计划日))。随机性来源是 UUID v4 的任务 ID，
对使用者不可预测；对系统自身可复现——进程重启/计划重算不产生漂移，
也不会把"已排好的随机时刻"重新洗牌（避免提前泄漏或意外重复）。
备选真随机（每次重算重新摇号）因不可复现被否决。

### ADR-006 声音检测 v1：能量阈值 VAD ✅ / v2：YAMNet TFLite

v1 用 16kHz PCM 流的 RMS dBFS 阈值判定：零模型依赖、低功耗、可解释，
满足"检测到声音 → 响应"的核心诉求；YAMNet（521 类声音事件，TF-Lite
int8 ~4MB）作为 v2 分类增强，接口已预留（SoundEvent 增加分类字段）。

### ADR-007 音频播放：just_audio + audio_session ✅

支持 gapless、音量曲线（淡入淡出）、随机时长裁剪；audio_session 统一
管理音频焦点，media/alarm 双通道映射（USAGE_MEDIA / USAGE_ALARM）。
备选 audioplayers（底层同样封装 ExoPlayer/AVPlayer，但音量曲线能力弱）。

## 3. 平台差异矩阵

| 能力 | Android | iOS |
|---|---|---|
| 常驻后台 | 前台服务（常驻通知） | 后台音频模式仅播放期间有效 |
| 被杀后触发 | 精确闹钟看门狗重新拉起 | 本地通知（≤30s 音）兜底 + BGAppRefresh 刷新计划 |
| 开机自启 | BOOT_COMPLETED（受 Android 15 类型约束，见 docs/05） | 不可（平台限制） |
| 声音检测 | 前台服务 microphone 类型（前台启动） | 后台 playAndRecord 会话 |
| Doze 应对 | 白名单 + AllowWhileIdle | N/A |
| 厂商杀后台 | 引导页深链（8+ 厂商） | N/A |
| 精确闹钟权限 | SCHEDULE_EXACT_ALARM（12+ 用户授权） | 无对应限制 |

## 4. 线程与隔离模型

```
主 isolate（UI）
  └─ go_router / Riverpod / 页面渲染
      │ MethodChannel: sonic_shield/native      （UI → 平台）
      │ flutter_background_service 事件桥        （UI ↔ 引擎）
后台 isolate（引擎，@pragma('vm:entry-point')）
  ├─ DartPluginRegistrant.ensureInitialized()
  ├─ 独立打开 AppDatabase（sqflite 线程安全）
  ├─ Timer 通道A循环
  └─ SoundGuardService 流式检测
原生线程
  ├─ AlarmManager → AlarmWatchdogReceiver（RTC_WAKEUP）
  └─ BootReceiver（开机）
```

要点：UI 与引擎通过「数据库 + 服务事件」通信而非共享内存，
任一侧崩溃重启都不丢状态。

## 5. 安全与隐私设计

1. v1 不申请 INTERNET 权限，数据全部本地；
2. 麦克风数据仅在内存计算能量，原始 PCM 不落盘；
3. 录音取证文件保存在应用私有目录，文件名带 `.evidence.m4a` 标记并
   列入 .gitignore，不参与媒体库扫描；
4. 权限按需申请，拒授后功能降级而非崩溃；
5. 方法通道校验调用来源（仅本应用）；PendingIntent 全部 FLAG_IMMUTABLE。
