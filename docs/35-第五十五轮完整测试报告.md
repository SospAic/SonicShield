## 35.2 本轮为什么值得单独一轮：DGC 的**结构性盲区**

第五十四轮的反漂移抽查抓到 6 处「当前基线」落点仍停在第 49/51 轮数字。**这不是产品缺陷，是文档缺陷** ——
但它暴露了机器锁的一个**能力边界**：

| 数字 | 分数 | 百分比 |
|---|---|---|
| 第四十九~五十二轮值 | `9298/9596` | `96.8953…%` → **96.89%** |
| 第五十三 / 五十四轮值（真值） | `9299/9597` | `96.8948…%` → **96.89%** |
| 第四十九~五十二轮值 | `9300/10086` | `92.2094…%` → **92.21%** |
| 第五十三 / 五十四轮值（真值） | `9301/10087` | `92.2097…%` → **92.21%** |

⇒ 两组数字**百分比完全相同**。而 DGC（第一组机器锁）的判据是
`COVERAGE_MIN` / `MIN_COVERED` **阈值** + `measuredPct` **百分比** + 百分比与分数的**自洽性** ——
`9298/9596` 与 `9299/9597` 在这三条上**都合法** ⇒ **判绿**。

**结论**：不动 DGC 的判据（它的职责是「阈值不许漂」），**另立一组 BAS 锁**（职责是「绝对分数不许漂」）。

## 35.3 新增：`BAS` 基线绝对分数一致锁（11 例）

位置：`test/doc_gate_consistency_test.dart`（与 DGC 同文件，机器锁仍保持 **4 个文件**的编排）。

### 真源怎么选（唯一的硬约束：必须能在干净克隆上判绿）

| 候选 | 能否当真源 | 理由 |
|---|---|---|
| `coverage/lcov.info` | ❌ | **被 `.gitignore` 排除**（`.gitignore:9` `coverage/`）⇒ 干净克隆 / CI 上不存在，锁会**假红** |
| `_pt/<轮次>gate.txt` | ❌ | 本地临时产物，不入库 |
| **`docs/12` / `docs/17` 的每轮最新顶级章节** | ✅ | 现场写就、**离门禁最近**；二者**互为交叉校验** |
| 其余落点（README / docs/00 / docs/09 / docs/21 / docs/22 / HANDOVER / CHANGELOG） | ✅（作**被检查方**） | 必须**逐位含有**根节声明的绝对分数 |

### 判据清单

| 用例 | 判据 |
|---|---|
| `BAS-01` | 两个权威根节各须有**唯一**一条可测面 / 全局 `X%（A/B）` 断言；**解析不到即红，不许跳过** |
| `BAS-02` ★ | 两个根节的绝对分数**逐位一致**（防两节互相漂移） |
| `BAS-03` ★ | 豁免面几何：`全局分母 − 可测面分母 == 490`（= 454 + 36）且 `全局分子 − 可测面分子 == 2` |
| `BAS-04` ★ | 7 个落点必须**逐位含有**根节的 `9299/9597` 与 `9301/10087` |
| `BAS-05` | 权威基线百分比与分数自洽（±0.05pt） |
| `BAS-06` | 端到端判定器在**真实仓库文本**上判绿 |
| `BAS-90a…e` | 反面样本：根节改一位 / 落点改一位 / 落点删分数 / 豁免几何 +1 / 根节塞第二条不同基线 —— **必须全部判红** |

### 反向自检（判据非恒真）

- `BAS-90a…e` **五条全部在真实文本上实测判红** ⇒ 判据不是恒真断言。
- **实施留痕**：首跑 `_pt/be1.txt` 时 `BAS-01 / BAS-02 / BAS-06` **判红** —— 原因是
  `docs/17` 最新节（当时为 §84）**没有权威基线行**。补写 §85 后转绿。
  ⇒ 本锁的「解析不到即红」纪律**第一次运行就在响**。
- 另有一个**样本构造坑**（首跑 `_pt/be2_locks.txt` 抓到）：`BAS-90b` 原本用 `replaceFirst` 改 `README.md`，
  但该文件里这对分数出现**两次** ⇒ 样本改完仍含真值，反例空转。改为 `replaceAll` + 显式断言
  「改完不含真值」后转绿。

### ⚠️ 新增文档约定（本锁依赖，必须遵守）

`docs/12` 与 `docs/17` 的**每轮最新节**必须写一行：

```text
**宿主基线（权威）**：可测面 X%（A/B） / 全局 Y%（C/D）
```

且**该节内不得再出现第二条「互不相同」的可测面 / 全局基线断言**（引用历史值时只写裸分数）。
否则 `BAS-01` 会因「真源不唯一」判红 —— 这是**刻意**的：锁宁可报到人面前，也不自己挑一条相信。

## 35.6 诚实边界（本节不允许被读成别的意思）

- 本轮**零生产代码改动** ⇒ 覆盖率**持平是如实结果**，不是「测不动了」；
  功能层由 1974 变 **1985** 的唯一原因是**新增了 11 例文档锁**，不是新增了被测行为。
- **BAS 的能力边界**：它只保证「**文档之间互相一致**」。项目里**没有**受版本控制的真值载体
  （`lcov.info` 被 gitignore）⇒ 若所有落点**同时**漂到**同一个**错值，本锁**抓不到**。
  这一条已写进锁的文件头注释，**不许**被读成「绝对分数从此不可能漂移」。
- 100% 覆盖率在宿主门禁内**仍不可达**（残差 **786 = 298** 可测面碎片终态 + **488** 设备层豁免）；
  本轮**未**为覆盖率写任何测试，**未**改动阈值。
- 设备层 22 + 6 例**不计入**宿主 lcov（`integration_test` 不在门禁分母）。
- 本轮**未抓修任何产品缺陷**。
