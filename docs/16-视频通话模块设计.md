# 16 · 视频通话模块设计（v1.4，方案 A）

> 能力：App 内向已配对端点发起视频/语音通话，被叫端可**自动接通**。
> 定位：家人守护（老人/儿童看护）与本人设备间协作。
> 选型：**WebRTC P2P（flutter_webrtc）+ 声盾 MQTT E2EE 信令**（方案 A）。
> 落选：云 SaaS（声网/TRTC，隐私定位冲突）、自建 SFU（单人对单人过重）。

---

## 1. 架构与信令

```
呼叫端                                          被叫端
call.invite {callId,video,sdp} ──MQTT E2EE──► 自动接通判定 → setRemote(offer)
call.candidate {ice}        ◄────────►        onIceCandidate 互发
        ◄───────────── call.answer {sdp} ──────────────
        ◄═══════ DTLS-SRTP 媒体直连（P2P） ═════════►
call.end {reason} ─────────────────────────► teardown
```

- 信令复用 v1.2 远程模块：配对密钥 → HKDF → AES-256-GCM；AAD 绑定主题；
  时间窗 + 去重防重放——**信令层零新增安全面**。
- 媒体：WebRTC 内建 DTLS-SRTP（传输加密），P2P 直连不经服务器。
- ICE：Google 公共 STUN ×2；对称 NAT 需自建 TURN（v1 不内置，v1.5 评估）。

## 2. 状态机（CallPhase）

```
idle → ringing（被叫）/ connecting（主叫）→ connected → ended → idle
```

- 主叫：getUserMedia → createOffer → setLocal → invite → setRemote(answer)
- 被叫：invite → 自动接通判定 → getUserMedia → setRemote(offer) →
  createAnswer → 回 answer
- Phase 经 Stream 广播给 UI（Overlay 全屏来电/通话界面）。

## 3. 自动接通

- 设置项 `rc_call_auto_answer`（默认关闭），仅对**已配对设备**生效；
- 占线保护：通话中收到新 invite → 自动回 `call.end{reason:busy}`；
- **平台限制（诚实声明）**：
  1. 被叫 App 进程存活（端点服务运行）时才可能自动接通——强杀后
     broker 无法唤起进程；
  2. Android 14+ while-in-use：camera|microphone FGS 必须前台启动——
     自动接通路径为「fullScreenIntent 亮屏 → 前台接通」，后台静默
     开摄像头不存在（平台禁止，且产品上明令禁止，见 §6）；
  3. 摄像头/麦克风权限需提前授予（开启自动接通时引导申请）。

## 4. UI 与路由

| 页面 | 路由 | 内容 |
|---|---|---|
| 呼叫页 | `/remote/call` | 端点单选（RadioGroup）+ 视频/语音呼叫按钮 + 自动接通开关 + 合规提示 |
| 来电/通话覆盖层 | Overlay | 全屏黑底：来电态显示接听/拒接；接通态显示媒体占位 + 挂断 |

- `CallService.bindStore()` 由 main.dart 注入（ICE 候选发送需要）；
- 手动接听模式下 `onManualRing` 回调当前也走自动接通（v1.4 简化，
  v1.5 拆分「仅响铃待确认」模式）。

## 6. 合规红线（不可协商）

1. **仅限本人设备或已获明确授权的设备**（配对即授权记录）；
2. **无隐蔽模式**：接通即亮屏、通话 UI 可见、系统摄像头指示灯正常——
   平台层面 Android 14+ 也禁止后台静默开摄；
3. 在他人不知情时开启其摄像头/麦克风属侵犯隐私，可能涉刑——
   本应用不提供、不会提供该能力；
4. 文档与商店话术统一为「家人守护视频通话」。

## 8. 关于「免同意控制」的安全决策

需求评估结论（2026-09-14）：**「未经对端同意直接控制他人设备」不予实现**——
技术上可行，但属未授权访问（多数辖区刑事犯罪），违反 docs/08 红线。
合法替代：**二维码扫码配对**（物理在场即强同意证明，比手输配对码更便捷）+
已配对设备自动信任（v1.2 现状）。此决策同时保护设备持有方，
是 KDE Connect 等行业产品的共同选择。
