## 三、前端样式评审

> 透镜：`refactoring-ui-design`（7 维度）+ `material-design`（设计审计 Checklist）

### 3.1 维度一 · 层级先于色彩 ❌

**现状**：全库硬编码 `fontSize` **111 处**，而走主题的 `textTheme.*` 仅 **57 处**。

```
fontSize: 11   ×8
fontSize: 12   ×89   ← 占 80%
fontSize: 13   ×8
fontSize: 14   ×2
fontSize: 18   ×2
fontSize: 24   ×2
```

`textTheme` 侧使用最多的是 `titleMedium`(32) / `bodySmall`(10) / `titleSmall`(3) / `titleLarge`(3) / `bodyMedium`(3)。

**问题**：M3 Type Scale 里 `Body Medium = 14`，但项目把正文压到 **12**（89 处），且 `12` 恰好**不在** M3 的 15 级阶梯里（M3 最小正文是 12 = `Body Small`，但 89 处显然不只是"辅助文字"）。结果是**排印层级被压平**：标题 12、正文 12、辅助 12 并存，层级只能靠字重和颜色硬撑。

**改法（可直接抄）**：把 111 处硬编码按语义映射回 `textTheme`，只在确有需要时才用 `copyWith`。

```dart
// ❌ 现状（lib/features/remote/remote_console_tab.dart 等多处）
Text('端点已连接', style: const TextStyle(fontSize: 12, color: Colors.grey))

// ✅ 建议：正文走 bodySmall，标题走 titleSmall —— 字号由主题统一供给
Text('端点已连接', style: Theme.of(context).textTheme.bodySmall)
Text('远程控制台', style: Theme.of(context).textTheme.titleMedium)
```

> 收益：`theme.dart` 一处改字号 → 全站生效；暗色模式对比度由 `colorScheme` 统一保证。

### 3.2 维度二 · 留白即信息 ❌

**现状**：`EdgeInsets.*` 出现 **16 种**数值：

```
 0×1   2×8   4×24   6×15   8×24   10×2   12×50   14×12
16×38  20×4  24×7   32×4   40×1   56×5   96×1
```

**问题**：`12 / 14 / 16` 三者混用（50 + 12 + 38 = 100 处），`6 / 10 / 20` 又各占一档。这**不是间距标尺**，是逐处目测的结果。Refactoring UI 的第一原则是"留白要有节奏"——相邻层级用**固定倍率**（4/8/12/16/24/32）。

**改法**：建 `AppSpacing` 常量（项目当前已有 16 处 `Spacing` 引用，可在此收敛）：

```dart
// lib/core/theme.dart 追加
abstract final class AppSpacing {
  static const xs = 4.0;
  static const sm = 8.0;
  static const md = 12.0;
  static const lg = 16.0;
  static const xl = 24.0;
  static const xxl = 32.0;
}
```

随后按"就近吸附"规则把 `6→8`、`10→8`、`14→16`、`20→24` 归一。**建议先只改 3 个最常用的屏幕**（dashboard / settings / remote），验证观感后再铺开。

### 3.3 维度三 · 色彩克制 ❌（本轮最严重）

**现状**：`lib/core/theme.dart` 定义 4 个品牌色，全库引用情况：

| 常量 | 定义值 | 全库引用次数 |
|---|---|---|
| `shieldDeep` | `0xFF0B3B3C` | **0** |
| `shieldMid` | `0xFF14666B` | **1**（`theme.dart` 自身 seedColor） |
| `alertAmber` | `0xFFFFB300` | **0** |
| `danger` | `0xFFC62828` | **1** |

**问题一**：`theme.dart` 共 47 行，其中 4 行是品牌色常量；**除 `shieldMid` 作为 seed 外，其余 3 个常量对 UI 零影响**。`shieldDeep` 与 `alertAmber` 是纯粹的死代码——文档里"品牌色：深青（盾）+ 琥珀（警报）"这句话，代码里没有兑现。

**问题二**：`danger` 的色号被**手工复制**而非引用：

```dart
// lib/features/remote/call_screen.dart:238
color: Color(0x14C62828),        // ← 0x14 是 8% alpha 前缀，色号 0xC62828 == AppTheme.danger

// lib/features/remote/remote_screen.dart:446
color: Color(0x14C62828),        // ← 同一处复制
```

改品牌红时要改 3 个地方，且**没有任何锁会提醒漏改**。

**问题三**：`Colors.*` 直接调用 **25 处**（white 11 / red 4 / white70 2 / green 2 / black 2 / black54 / transparent / orange / deepOrange）。

> **需要澄清的例外（不算缺陷）**：其中 18 处 `Colors.white/black/black54` 集中在**视频通话与全屏覆盖层**（`call_screen` / `call_incoming_overlay` / `multi_video_screen` / `ptt_tab` / `remote_screen:714`）。这些页面刻意用**纯黑底 + 白字**（视频画面铺底），属于合理设计，**不建议改成主题色**。真正该收敛的是 `Colors.red/green/orange/deepOrange` 那 8 处（语义色应走 `colorScheme.error` / 自定义 `AppTheme` 语义色）。

**改法**：

```dart
// ① 收敛语义色，供日志级别等复用
abstract final class AppColors {
  static const success = Color(0xFF2E7D32);
  static const warning = Color(0xFFF9A825);
  static const danger  = Color(0xFFC62828);   // 从 AppTheme.danger 迁来，保持单一来源
}

// ② call_screen:238 / remote_screen:446 改为引用
color: AppColors.danger.withValues(alpha: 0.08),

// ③ log_screen:142-144 的级别色
switch (level) {
  'success' => AppColors.success,
  'failed'  => AppColors.danger,
  _         => AppColors.warning,
}
```

**加锁建议**（`doc-criterion-to-mechanical-guard` 的思路）：新增一条源码锁，断言 `lib/features/**` 下**不出现** `Colors.red|green|orange|deepOrange`，且不出现 `Color(0x...C62828)` 字面量。

### 3.4 维度四 · 深度与层级 ✅
