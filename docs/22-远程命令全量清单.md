### 1.3 协助会话命令（独立命名空间，5 条）

`assist.*` 与配对遥控**命名空间隔离**（不同 MQTT 主题、不同密钥派生），**不计入表 A**：
`assist.hello`（控制端→端点）、`assist.accept` / `assist.reject` / `assist.perm` / `assist.close`（端点→控制端 / 双向）。
它们只做握手与权限下发，**本身不构成设备操控能力**。证据：`assist.dart:317-321`（5 条常量）；
路由 **`endpoint_service.dart:399-406`**（按 `RcAssist.topicPrefix` 精确判主题，不是旧写的 `:307-314`）。
收发两端已逐条核实（详见 §12 §12.5）：`hello` 发=`assist_join.dart:221` 收=`assist_host.dart:324`；
`accept` 发=`assist_host.dart:433` 收=`assist_join.dart:358`；`reject` 发=`assist_host.dart:444` 收=`assist_join.dart:372`；
`perm` 发=`assist_host.dart:256-261` 收=`assist_join.dart:377`；`close` 双向（发 `assist_host.dart:206` / `assist_join.dart:250`，
收 `assist_host.dart:326` / `assist_join.dart:385`）。

**协助会话权限位（8 位，默认全拒）**：`media` 播放音效 / `tts` 语音喊话 / `vibrate` 震动 / `volume` 调节音量 /
`location` 获取定位 / `video` 视频通话 / `script` 执行指令组与改写自动化 / `audit` 查看审计日志。
命令→权限位的映射是**唯一真源**（`RcPermGate.requiredPerm`，`assist.dart:351-392`），控制端与端点共用同一张表 ——
避免「按钮可点但命令被拒」或「按钮灰着其实能发」的双向漂移。
8 个位**全部有实际运行期执行点**（命令级 `assist_host.dart:347-363`；步骤级 `endpoint_service.dart:1366-1379`），
本轮未发现「登记了却从不执行」的位。

> ⚠️ **`script` 位是事实上的宽权限位**（本轮 `*W3*` 确认，而非新发现）：它同时门控 8 条命令，含
> `task.upsert` / `task.delete`（全量改写自动化）与 `task.runNow`（立即执行任意本机任务）。
> 而本机任务动作类型包含 `recordEvidence` / `tts` / `vibrate` / `playAudio`（`lib/domain/models/action.dart:3-14`），
> 且 `TaskWire.fromWire` 对 `actionType` 是**全枚举解析**（`task_wire.dart:147-159`，没有白名单裁剪）。
> ⇒ **只放行 `script` 一个位的协助方，可以新建一条 `actionType:'recordEvidence'` 的任务再 `task.runNow` 触发录音**，
> 绕开步骤级闸门对 `record` 的 `denyAll`（`assist.dart:423`）。这与本节「采集红线」和 §9 第 3 条的承诺**构成实质矛盾** —— 详见 §12 D-7。
