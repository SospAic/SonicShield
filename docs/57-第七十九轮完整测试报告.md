## 二、本轮主题 A：夜间豁免三态化

**问题**：旧实现 `Task.quietExempt` 是二态 `bool`（开 / 关），无法表达"**显式跟随全局主开关**"与
"**显式强制豁免**"的区别 —— 用户把某任务设成"不豁免"后，一旦主开关打开，该任务会被静默豁免，
与用户意图相反。

**方案**：`Task.quietExempt` 由 `bool` → **`bool?`**，三态语义：

| 值 | 语义 |
|---|---|
| `null`（默认） | **跟随**全局主开关 `PrefsKeys.quietExemptMaster` |
| `true` | **强制豁免**（即使在夜间也执行） |
| `false` | **强制不豁免**（即使主开关开着也照常执行） |

- 判定收敛为单一表达式：`exempt = taskExemptOverride ?? allowQuietExempt`（**不静默**：显式值优先）。
- 设置页「例外清单」只列 `t.quietExempt != enabled` 的**显式偏离项**，不再把跟随主开关的任务混进去。
- 回归锁：`test/quiet_exempt_lock_test.dart` 新增 `QE-P1`（真实库往返：`forceRun` 只收"强制执行"；
  `quietExemptOverride` 只收"显式设置过"的项）。

## 三、本轮主题 B：节假日全局执行总开关

**新增纯函数** `lib/domain/scheduling/run_pause.dart`（**无 I/O，可完全单测**）：

- **三态模式** `RunMasterMode{auto,on,off}`：`auto` 跟随窗口 / `on` 恒运行 / `off` 恒暂停；
  `parse()` 容错（读不懂 → `auto`，与出厂默认一致，**不抛**）。
- **暂停窗口**：围绕每个「连续休息日块」`[S, E]`（由 `ChinaHolidays` 判定，**含普通周末**）⇒
  窗口 = `[S 前一天 20:00, E 当天 21:00)`（**半开区间**：20:00 整点进暂停、21:00 整点恢复）。
  逐日判定即可（无需枚举块）：

  | 当天 | 次日 | 是否在窗口 |
  |---|---|---|
  | 非休息日 | 休息日 | `>= 当天 20:00`（假期前夜） |
  | 休息日 | 休息日 | 恒 `true`（块中间） |
  | 休息日 | 非休息日 | `< 当天 21:00`（块最后一天） |
  | 非休息日 | 非休息日 | `false` |

- **复用 `ChinaHolidays` 覆盖表**（与反击计划同源）⇒ 避免"用户把某天改成工作日"只影响一处。
- 配套 `windowEnd` / `nextStart` / `paused` / `nextTransition`（供 UI 显示"下次切换"）。
- **任务级强制例外** `Task.forceRun`：暂停窗口内仍执行。
- **DB v4 → v5**：`app_database.dart` `dbVersion` 4 → 5，**幂等补列** `tasks.force_run`。
- **远程命令** `RcCmd.runMasterSet = 'run.master.set'`（`endpoint_service._setRunMaster`）：
  合法 mode 落库 + 审计成功 + 请求引擎重排；**非法 / 缺参显式失败且不写库（不静默回落 `auto`）**；
  已写库但重排失败时审计如实失败、回执区分 `replan=failed`。
  ⚠️ **合规红线**：远程**不得**写 `PrefsKeys.quietExemptMaster`（夜间豁免主开关）—— 只允许写 `run_master_mode`。
