# 07 · 数据模型与存储设计

> 对应实现：`lib/data/db/app_database.dart`（建表 SQL v1）

---

## 1. ER 总览

```
tasks 1 ──── n occurrences          （任务 → 物化计划，外键级联删除）
tasks n ─── n audio_assets          （音源池，task.asset_ids JSON 数组按 id 引用）
tasks 1 ─── n exec_logs             （执行审计）
sound_profiles（全局单例行 id='default'，守卫参数）
kv（轻量配置：合规确认、电源模式、免打扰时段…）
```

## 2. 表结构（v1 DDL 摘要）

### tasks
| 列 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | UUID v4 |
| name | TEXT NOT NULL | 任务名 |
| enabled | INTEGER 0/1 | 启停 |
| trigger_type | TEXT | fixedOnce/dailyAt/weeklyAt/randomWindow/randomInterval/soundTriggered |
| trigger_json | TEXT | TriggerConfig 序列化（sealed 类多态） |
| action_type / action_json | TEXT | ActionConfig 同上 |
| asset_ids | TEXT(JSON 数组) | 音源池 |
| cooldown_sec | INTEGER | 冷却（执行期与物化期双重生效） |
| quiet_policy | TEXT | skip / shift |
| priority | INTEGER | 同刻冲突排序 |
| created_at / updated_at | INTEGER(ms) | 审计 |

索引：`idx_tasks_enabled(enabled)`

### occurrences（计划状态机，引擎核心）
| 列 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | `{taskId}@{fireAtMs}`；声音触发为 `{taskId}@sound@{ts}` |
| task_id | TEXT FK→tasks ON DELETE CASCADE | |
| fire_at | INTEGER(ms) | 触发时刻 |
| status | TEXT | pending / done / failed / skipped |
| volume | REAL? | 物化期敲定的执行音量（审计） |
| duration_ms | INTEGER? | 物化期敲定的执行时长 |

索引：`idx_occ_fire(fire_at)`、`idx_occ_status(status)`

### audio_assets / exec_logs / sound_profiles / kv
- audio_assets：id、name、path（应用私有目录）、duration_ms、size_bytes、
  tags(JSON)、weight（加权随机）、created_at；
- exec_logs：自增 id、task_id、occurrence_id、source(schedule/sound/manual/
  evidence)、action、status(success/failed/skipped)、volume、duration_ms、
  message、created_at；索引 created_at；
- sound_profiles：threshold_db、min_duration_ms、cooldown_sec、
  only_while_charging、enabled；
- kv：字符串 KV（合规确认标志、quiet_start/end、power_mode…）。

## 3. 设计取舍

1. **JSON 配置列**：trigger/action 是多态 sealed 类，结构演进频繁；
   核心查询路径（enabled/status/fire_at）保持强类型列+索引，
   两全其美。反序列化容错：未知 kind 抛 ArgumentError（fail-fast）。
2. **occurrences 独立成表而非内存队列**：进程被杀/重启后状态可恢复；
   双通道触发靠它天然幂等（主键 OR IGNORE + 状态机）。
3. **外键级联**：`PRAGMA foreign_keys=ON`；删任务即清理计划，
   杜绝"幽灵触发"。
4. **exec_logs 独立自增主键**：高频追加，与业务主键解耦，便于按期清理。

## 4. 数据生命周期

| 数据 | 保留策略 |
|---|---|
| 非 pending occurrences | 7 天后由维护任务清理（purgeOlderThan） |
| exec_logs | 90 天（可在设置调整），导出后可清空 |
| 录音取证文件 | 永不自动删除（用户资产）；提供手动清理与导出 |
| kv | 永久（轻量） |

## 5. 备份与恢复

- v1：Android Auto Backup（自动，含数据库与 prefs）；
  取证文件因隐私默认排除云备份（可设置显式开启本地导出）。
- 导出：日志 CSV 导出（share_plus）；取证文件原样复制到用户选择目录。
- v2 规划：加密全量备份（用户口令 AES-GCM）。

## 6. 迁移路径

- 版本号 `dbVersion` 递增 + `onUpgrade` 顺序迁移脚本；
- JSON 配置列向前兼容策略：解析失败视为未知类型并告警（不崩溃）；
- v2 若引入 Drift（ADR-003）：Drift 可直接挂接现有 SQLite 文件，
  表定义映射现有 schema，无数据迁移成本。
