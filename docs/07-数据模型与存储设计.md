# 07 · 数据模型与存储设计

> 对应实现：`lib/data/db/app_database.dart`（建表 SQL v1）

---

## 1. ER 总览

```
tasks 1 ──── n occurrences          （任务 → 物化计划，外键级联删除）
tasks n ─── n audio_assets          （音源池，task.asset_ids JSON 数组按 id 引用）
tasks 1 ─── n exec_logs             （执行审计）
sound_profiles（全局单例行 id='default'，守卫参数）
kv（轻量配置：合规确认、电源模式、免打扰时段…）
```

## 2. 表结构（v1 DDL 摘要）

### tasks
| 列 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | UUID v4 |
| name | TEXT NOT NULL | 任务名 |
| enabled | INTEGER 0/1 | 启停 |
| trigger_type | TEXT | fixedOnce/dailyAt/weeklyAt/randomWindow/randomInterval/soundTriggered |
| trigger_json | TEXT | TriggerConfig 序列化（sealed 类多态） |
| action_type / action_json | TEXT | ActionConfig 同上 |
| asset_ids | TEXT(JSON 数组) | 音源池 |
| cooldown_sec | INTEGER | 冷却（执行期与物化期双重生效） |
| quiet_policy | TEXT | skip / shift |
| priority | INTEGER | 同刻冲突排序 |
| created_at / updated_at | INTEGER(ms) | 审计 |

索引：`idx_tasks_enabled(enabled)`

### occurrences（计划状态机，引擎核心）
| 列 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | `{taskId}@{fireAtMs}`；声音触发为 `{taskId}@sound@{ts}` |
| task_id | TEXT FK→tasks ON DELETE CASCADE | |
| fire_at | INTEGER(ms) | 触发时刻 |
| status | TEXT | pending / done / failed / skipped |
| volume | REAL? | 物化期敲定的执行音量（审计） |
| duration_ms | INTEGER? | 物化期敲定的执行时长 |

索引：`idx_occ_fire(fire_at)`、`idx_occ_status(status)`

### audio_assets / exec_logs / sound_profiles / kv
- audio_assets：id、name、path（应用私有目录）、duration_ms、size_bytes、
  tags(JSON)、weight（加权随机）、created_at；
- exec_logs：自增 id、task_id、occurrence_id、source(schedule/sound/manual/
  evidence)、action、status(success/failed/skipped)、volume、duration_ms、
  message、created_at；索引 created_at；
- sound_profiles：threshold_db、min_duration_ms、cooldown_sec、
  only_while_charging、enabled；
- kv：字符串 KV（合规确认标志、quiet_start/end、power_mode…）。

## 3. 设计取舍

1. **JSON 配置列**：trigger/action 是多态 sealed 类，结构演进频繁；
   核心查询路径（enabled/status/fire_at）保持强类型列+索引，
   两全其美。反序列化容错：未知 kind 抛 ArgumentError（fail-fast）。
2. **occurrences 独立成表而非内存队列**：进程被杀/重启后状态可恢复；
   双通道触发靠它天然幂等（主键 OR IGNORE + 状态机）。
3. **外键级联**：`PRAGMA foreign_keys=ON`；删任务即清理计划，
   杜绝"幽灵触发"。
4. **exec_logs 独立自增主键**：高频追加，与业务主键解耦，便于按期清理。

## 4. 数据生命周期

| 数据 | 保留策略 |
|---|---|
| 非 pending occurrences | 7 天后由维护任务清理（purgeOlderThan） |
| exec_logs | 90 天（可在设置调整），导出后可清空 |
| 录音取证文件 | 永不自动删除（用户资产）；提供手动清理与导出 |
| kv | 永久（轻量） |

## 5. 备份与恢复

- v1：Android Auto Backup（自动，含数据库与 prefs）；
  取证文件因隐私默认排除云备份（可设置显式开启本地导出）。
- 导出：日志 CSV 导出（share_plus）；取证文件原样复制到用户选择目录。
- v2 规划：加密全量备份（用户口令 AES-GCM）。

## 6. 迁移路径

- 版本号 `dbVersion` 递增 + `onUpgrade` 顺序迁移脚本；
- JSON 配置列向前兼容策略：解析失败视为未知类型并告警（不崩溃）；
- **`dbVersion` 3 → 4（修复历史库缺列）**：v3 刚上线时 `onUpgrade` 只补了
  `tasks.quiet_exempt`，`occurrences.quiet_exempt` 是第五十三轮（BUG-079）才补的
  —— 在修复前升到 v3 的库 `user_version` 已是 3，`oldV < 3` 闸再也进不去，
  列永久缺失，导致 `commitAll`（`INSERT INTO occurrences` 带 `quiet_exempt`）
  每次抛 `no such column`，任务物化整链失败（三机实机取证）。v4 迁移改为
  **按列存在性幂等补齐**（`PRAGMA table_info` 判存在，`ALTER` 不支持
  `IF NOT EXISTS`），对 v1/v2/v3 及全新库都安全。回归锁：`test/app_database_migration_test.dart` 的 MIG-07；
- v2 若引入 Drift（ADR-003）：Drift 可直接挂接现有 SQLite 文件，
  表定义映射现有 schema，无数据迁移成本。

## 8. v1.9.0-alpha 变更（振动能力 + 夜间独立豁免）

> 对应 docs/20（振动能力设计）与 docs/12 §51（第二十六轮测试报告）。**`dbVersion` 2 → 3**。

### 8.1 新增动作类型（`action_type` / `action_json`）

`ActionConfig` 仍是 sealed 多态，**新增两个子类**（`lib/domain/models/action.dart`）：

| action_type | 类 | 关键字段（`action_json`） | 说明 |
|---|---|---|---|
| `randomVibrate` | `RandomVibrateAction` | `durationSecMin/Max`、`amplitudeMin/Max`、`gapMinMs/gapMaxMs`、`pulseMsMin/Max`、`rampUpSec`、`rampDownSec`、`dutyCycle`、`sharpness`、`respectDnd` | 随机节奏 + 随机强度的脉冲串 |
| `continuousVibrate` | `ContinuousVibrateAction` | 同上 + `chunkMs`（分片续发片长） | 一段时长内持续振动（**本地不设硬上限**，代价由 S1–S4 四条失效安全补上） |

⚠️ **不扩展 `VibrateAction`**：老 `vibrate` 的 `patternMs` 语义一字不改（向后兼容）——
把随机参数塞进同一个类会得到 nullable 字段汤，正是 BUG-068 的成因（docs/20 §4.1）。
消费侧靠 sealed 类的**穷尽 switch** 强制显式处理（新增子类忘补 = 编译报错）。

### 8.2 "计划即审计"扩展到振动

随机参数**不在执行期现算**，而是在 **materialize 期**由 DPRNG 敲定并落库：

| 列 | 振动语义 |
|---|---|
| `volume` | 本次敲定的**基准强度**（`amplitudeMin..amplitudeMax` 内） |
| `duration_ms` | 本次敲定的**总时长**（`durationSecMin..Max` 内） |

⇒ 同一 `occurrence.id` 必然复现同一曲线（`test/vibrate_resolve_test.dart` VR-10 / VR-19），
"为什么这次是 0.72 振幅"可回答。脉冲数被 `VibrateLimits.maxPulses` 封顶，
**截断必须显式留痕**（`plan.truncated` → 执行层写审计；VR-09 / VR-20）。

### 8.3 夜间独立豁免（双钥匙）

| 列 | 类型 | 说明 |
|---|---|---|
| `tasks.quiet_exempt` | INTEGER 0/1，默认 0 | 任务级钥匙（用户逐任务授权） |
| `occurrences.quiet_exempt` | INTEGER 0/1，默认 0 | 物化期从任务复制，供审计与"撤销后清理" |

主开关在 prefs（`PrefsKeys.quietExemptMaster = 'quiet_exempt_master'`），
**双钥匙皆开才放行**，缺一即回受约束。
⚠️ `commitAll` 用 `ConflictAlgorithm.ignore`（幂等语义）⇒ **撤销授权必须主动
`deletePendingQuietExempt()`**，否则已落库的豁免计划会继续生效
（`test/quiet_exempt_lock_test.dart` QE-24 端到端不变量锁）。

### 8.4 迁移

`_onUpgrade`：v2 → v3 两条 `ALTER TABLE ... ADD COLUMN quiet_exempt INTEGER NOT NULL DEFAULT 0`
（`tasks` 与 `occurrences` 各一条）。默认 0 = **未授权**；缺失/空值一律读作 false
（QE-21：降级到更安全的一侧，而不是"没配就是允许"）。
