## 三、P1 缺陷（2 条）

### 🔴 R90-01 内置 DeepSeek API Key 以真实凭据形态硬编码进仓库
- **位置**：`lib/data/repositories/api_config_store.dart:46-49`
- **证据**：
  ```dart
  static const String _builtInApiKey = String.fromEnvironment(
    'DEEPSEEK_API_KEY',
    defaultValue: 'sk-6c623340b8804850b3e6fe68452aeeac',
  );
  ```
- **场景**：任何拿到仓库或反编译 APK 的人都能提取该 Key，直接调用 `api.deepseek.com` 产生真实费用；且 `defaultApiKey` 作为"从未配置"时的回落值，使**用户显式清空 Key 也无法停用**该内置额度。
- **判定**：真实 `sk-` 形态凭据入库 = 密钥泄露，不是理论风险。注释里"这只是出厂默认"不改变"密钥已随源码分发"这一事实。
- **建议**：从源码移除 defaultValue（改为空串 + 首次使用引导），并**立即在 DeepSeek 控制台轮换该 Key**。

### 🔴 R90-02 legacy 对讲面板：无 60 秒上限、无松手守卫、关闭面板后录音不停
- **位置**：`lib/features/remote/remote_screen.dart:982-1033`（`_PttSheetState`）、`:484-492`（`showModalBottomSheet`）
- **证据**：
  ```dart
  Text(_recording ? '正在录音…（松开发送，最长 60 秒）' : ...),   // 文案承诺 60s，本类无任何 Timer
  GestureDetector(
    onTapDown: (_) => _start(),        // 跨 hasPermission + _rec.start 两段 await，无"是否仍按住"复核
    onTapUp: (_) => _stopSend(),
    onTapCancel: () => widget.onCancel(),
  )
  ```
  `_PttSheetState` 全文**无 `Timer`、无 `dispose()`**；面板以默认 `isDismissible: true` 弹出。
- **场景**：
  1. 按住说话 → 系统麦克风权限弹窗期间松手 ⇒ `_stopSend()` 先跑（返回"未录到音频"）⇒ `_start()` 随后完成并把 `_recording` 置真 ⇒ **一段无人控制的录音**；
  2. 录音中下滑关闭面板 / 返回键 ⇒ 面板销毁但 `onCancel` 未被调用 ⇒ **麦克风持续采集，界面已无任何入口可停**；
  3. 文案承诺的 60 秒上限在本类中**根本不存在**（无 ticker）。
- **对照**：同功能的 `ptt_tab.dart:33-63` 已有 `_pressing` 复核 + 60 秒 ticker + `dispose` 兜底（P2-25 修复）—— 本条是**孪生路径漏改**。
- **判定**：触碰项目"用户以为停了却还在录"的隐私红线，P1。
- **建议**：删除 legacy 面板改走 `ptt_tab` 同一实现；或在 `_PttSheetState` 补齐 `_pressing` 复核 + 60s `Timer` + `dispose(){ onCancel() }`，并把 `isDismissible:false` / `PopScope` 拦住下滑关闭。

## 四、P2 缺陷（13 条）

### ⚠️ R90-03 远程「立即执行」绕过全局执行总开关（节假日暂停）
- **位置**：`lib/services/background_engine.dart:2025-2060`（runNow 处理器），对照 `:904-946`（`admitExecution`）
- **证据**：`admitExecution` 第一道闸是 `if (!task.forceRun && pausedAt(DateTime.now()))` 并写明"供**声音**与**远程立即执行**两个入口复用"；但 runNow 实际只内联了 `conditionFailedIn` + `probabilityGateMissed`，**没有 pausedAt 判定**。
- **后果**：`runMasterMode=off` 或法定休息日暂停窗口内，远程 `task.runNow` 仍会播放/播报/振动 —— 全局刹车对远程路径静默失效，与同文件契约注释直接矛盾。

### ⚠️ R90-04 声音守卫计划把 `skipped` 落成 `done`，凭空激活冷却
- **位置**：`lib/services/background_engine.dart:1553-1562`（`runGuardPlan`），对照 `:1496-1499`（`executeDue` 的三态映射）
- **证据**：
  ```dart
  status: outcome.isFailure ? OccurrenceStatus.failed : OccurrenceStatus.done,  // skipped 被并入 done
  ```
  `executeDue` 已按 BUG-093 改为 `outcome.isSkipped ? skipped : (ok ? done : failed)`；声音入口漏改。
- **后果**：无振动器设备 / 平台未确认振动（`ExecutionOutcome.skipped('无振动能力')`、`'平台未确认振动'`，见 `:981`/`:1010`）会被记成"执行过" ⇒ `lastDoneFor` 非空 ⇒ 后续真实声音事件在冷却期内被压掉。

### ⚠️ R90-05 声音触发入口完全绕过免打扰策略，编辑器里的开关是死设置
- **位置**：`lib/services/background_engine.dart:1572-1592`（onSoundEvent → admitExecution）、`:904-946`（无 quiet 判定）；`lib/features/tasks/task_editor_screen.dart:1364-1369`（仍对声音任务显示豁免开关）
- **证据**：`materialize` 对 `SoundTrigger` 直接 `return const []`（不进时间计划），`admitExecution` 只查 pausedAt/条件/概率 —— **没有任何 `_applyQuiet` 调用**。而编辑器对所有触发器类型都渲染"本任务豁免免打扰（夜间独立豁免）"。
- **后果**：用户给声音任务设的 `quietPolicy`/`quietExempt` 永不生效；夜间 03:00 的异响会照常出声。**界面在说谎**，与 BUG-070 同族。
- **建议**：二选一并写进文档——① 声音入口接入 `_applyQuiet`（守卫告警可单独走 `forceRun` 例外）；② 明确"守卫不受免打扰约束"并在编辑器对声音任务隐藏该控件。

### ⚠️ R90-06 引擎停机清理链执行期间，15 秒 tick 仍在跑
- **位置**：`lib/services/background_engine.dart:1895-1974`（stop 链）与 `:2157-2197`（`Timer.periodic` 无停机闸门）
- **证据**：stop 链含多次 `await`（守卫停止 2s 超时、写库、两次 `broadcast`、末尾 150ms），期间 `Timer.periodic` 仍会触发 `executeDue` / `replan` / `pushExactAlarms`。
- **后果**：① `clearAllAlarms()` 后被并发 replan 重排闹钟；② `broadcast(running:false)` 后被 tick 的 `broadcast()` 覆盖 ⇒ UI 开关卡在"已开启"；③ `playback.stop()` 后被并发 `executeDue` 重新起播 ⇒ 用户停了引擎仍出声。
- **建议**：加 `_stopping` 同步闸门（stop 链第一行置位、`stopSelf` 前不复位），tick/executeDue/replan/pushExactAlarms 全部先查。

### ⚠️ R90-07 `PlaybackService` 单例播放器无跨路径互斥，并发播放互踩且都记成功
- **位置**：`lib/services/playback_service.dart:142-206`
- **证据**：`final player = _player ??= AudioPlayer(); _stopRequested = false;` —— `_player` 与 `_stopRequested` 都是**实例级**状态，没有 per-call 隔离；`_playing` 只用于批量停止，不做互斥。
- **并发来源**：`executeDue`（定时）与 `onSoundEvent→runGuardPlan`（声音）与远程 `runNow` 是三条独立异步链，可在同一 isolate 内重叠。
- **后果**：第二次 `play()` 对同一播放器 `setFilePath` 打断前一次；前一次的 `_hardStop` 又把后一次静音；两者 `_waitPlayWindow` 只数窗口不验播放器状态 ⇒ **两边都记 success**，occurrence 与日志双双失真。

### ⚠️ R90-08 DeepSeek 通路无明文端点校验，Bearer Key 可经 http 外发
- **位置**：`lib/services/deepseek_service.dart:118-134`；`lib/data/repositories/api_config_store.dart:143`（`setBaseUrl` 不校验协议）
- **证据**：`headers: {'Authorization': 'Bearer ${_config.apiKey}'}` 直接发往 `_config.chatCompletionsUrl`；项目已为 TTS 建了 `isSecureTtsEndpoint`（`online_tts_client.dart:326`，BUG-132）但**未复用到 DeepSeek**。
- **后果**：用户在设置页把基址填成 `http://…`（内网自建 / 手滑），API Key 与计划内容明文上网 —— BUG-132 堵过的形态在新通路复现。

### ⚠️ R90-09 单行损坏拖垮整张任务表（`Task.fromRow` 无逐行兜底）
- **位置**：`lib/domain/models/task.dart:138-160`、`lib/domain/models/trigger.dart:93-100`、`lib/domain/models/action.dart`（`_ => throw ArgumentError`）
- **证据**：`TriggerType.values.byName(...)`、`TriggerConfig.fromJson`（未知 kind 直接抛）、`ActionConfig.fromJson`（`_ => throw ArgumentError`）、`_decodeJson`（`jsonDecode` 裸调用）—— 任一失败都会从 `Task.fromRow` 抛出。

### ⚠️ R90-10 `RcScriptExecutor.run` 无 finally：一次通知失败永久焊死指令组通道
- **位置**：`lib/remote/script_executor.dart:192-291`

## 七、分区结论（功能点 / 调用链 / 层次 / 逻辑）

### 1. domain + core + data ✅ 层次纪律与事务语义良好
- **层次**：`lib/domain/**` 与 `lib/core/utils/**` **零** `package:flutter` / `sqflite` / `shared_preferences` 依赖 —— 纯领域层纪律成立。
- **调度逻辑**：日历推进统一走「年/月/日 +1」（DST 安全，BUG-095/096 已修）；随机窗口"整窗抽样 + 事后过滤"（P1-05）；冷却贪心过滤；续算判据 `planNeedsExtend` 改为覆盖末端（BUG-086）—— 均正确。
- **事务**：`TaskRepository.upsert` 单事务 UPDATE→INSERT（无 DELETE、不触发级联，BUG-147）；`reconcile` 单事务先删后插并按投影区分 skipped 意图/残影（BUG-092）；`commitAll` 用 `ConflictAlgorithm.ignore` 保持"计划即审计"。
