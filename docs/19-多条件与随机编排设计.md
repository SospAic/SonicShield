# 19 · 多条件 × 随机编排设计（v1.8）

> 需求：触发功能点支持**多条件组合**与**随机执行**——
> "到某时间点，随机播放声音中的某一个"、"符合随机条件时，随机执行某一指令"。
> 行业对标：Tasker（触发器 AND + 多动作）、iOS Shortcuts（Choose from List +
> Random Number）、IFTTT（单链 this→that）。

---

## 1. 两条正交机制

```
触发命中
   ▼
┌─────────────────────────────┐
│ 条件层（确定性，AND）        │  充电/电量/时段/Wi-Fi/通话保护
│ TaskCondition.firstUnmetIn  │  任一不满足 → skipped（审计原因）
└──────────────┬──────────────┘
               ▼ 全部满足
┌─────────────────────────────┐
│ 概率门（随机，P%）           │  掷 rng(100) < P → 通过
│ probabilityGateMissed()     │  未命中 → skipped（审计"概率 P% 未命中"）
└──────────────┬──────────────┘
               ▼ 通过
┌─────────────────────────────┐
│ 动作集（加权随机选一）        │  ActionSetAction.pick(rng)
│ candidates[{weight,action}] │  审计"权重 → 选中"（回溯）
└─────────────────────────────┘
```

**两层随机的分工**：
- 概率门回答"这次**执行不执行**"（二元随机）；
- 动作集回答"执行的话**执行哪一个**"（N 选一随机）。
- 两者可独立配置，也可叠加（先掷门、再选动作）。

## 2. 概率门（RandomGate）

- 字段：`TaskCondition.probabilityPct`（int，1–100；null/100 = 必执行）。
- 判定式：`rng.nextInt(100) < P` → 通过。**大样本分布验证**：
  P=50 时 20000 次频率 0.46–0.54；P=10 时 0.08–0.12（测试锁定）。
- 架构位置：**不在 `firstUnmet` 纯判定层**——判定必须幂等可测；
  概率门在引擎调用方（`probabilityGateMissed()`）确定性条件通过后执行，
  与"`now` 不进快照"同一先例（随机数同样是每次调用不同的输入）。
- 审计：`action=probability, status=skipped, message="概率 P% 未命中（掷出 N）"`。

## 3. 动作集（ActionSetAction）

- 结构：`candidates: [{weight: double, action: ActionConfig}]`，2–12 个候选。
- 选择算法：**加权随机**（`pick(rng)`：roll = rng·total，逐个减权重）；
  全零权重安全兜底为等概率（配置错误的容错行为，测试锁定两类动作都会出现）。
- 候选动作支持全部动作类型（播放/声景/TTS/通知/取证/震动）——
  即"随机播放声音中的某一个"（多个 PlayAudioAction 候选）与
  "随机执行某一指令"（TTS/通知/取证/震动混合候选）都成立。
- 审计：执行前写 `action=randomFrom, message="权重 W → 选中 <类型>"`，可回溯。

## 4. 组合集合（行业谱系全覆盖对照）

| 组合需求 | 声盾实现 | 状态 |
|---|---|---|
| 多条件 AND（充电+电量+时段+Wi-Fi+通话） | TaskCondition 全字段 AND | ✅ v1.7 |
| 触发后概率执行（"随机条件"） | probabilityPct 概率门 | ✅ v1.8 |
| N 选一随机动作 | ActionSetAction 加权随机 | ✅ v1.8 |
| 概率门 + 动作集叠加 | 先掷门、再选一（正交可叠加） | ✅ v1.8 |
| 条件 OR | 拆成多个任务（行业同法：MacroDroid 也无原生 OR） | 备选 |
| 动作序列 + 时延 | RcScript（远程指令组已交付；本地任务 v2 评估） | 远程已 ✅ |
| If/Else 分支动作 | 概率门 + 双任务（各配 P 与 100-P）等价实现 | 备选 |
| 循环/重试 | 超出当前合规定位（循环播放已有 loopFill） | 不做 |

## 5. UI（任务编辑器）

- **条件区**：新增"执行概率"滑条（5–100%，100=每次都执行）。
- **动作区**：新增"随机指令集"类型 → 候选动作列表（ActionChip 添加 5 类、
  每候选权重滑条 0–10、可删除），上限 8 候选。
- 回填：编辑已有任务时 `ActionSetAction` → 候选/权重完整还原
  （`_kindOfCandidate` 从 ActionConfig 反推种类）。
- 校验：候选 < 2 时保存给出提示（模型 assert ≥2，UI 层温和提示）。

## 7. 引擎接线

- `executeDue()`（调度触发）与 `onSoundEvent()`（声音触发）双入口：
  确定性条件通过后 → `probabilityGateMissed()` → 未命中 skipped+审计。
- `runSingle()` switch 新增 `ActionSetAction` 分支：
  `pick` → 审计"权重→选中" → 递归 `runSingle(选中项)`。

## 8. 互通探针（`tool/rc_probe.dart`）

多机远程"可用性 / 准确性"的自动化验证工具：以**控制器身份**直连 broker，
向已配对端点发真实加密命令，**解密回执并核对命令 id**。

### 8.1 密钥模型（最易搞错的地方 —— BUG-052）

协议按**接收方身份**派生密钥（见 docs/14）：

| 方向 | 主题 | 密钥 |
|---|---|---|
| 控制器 → 端点 | `sonicshield/v1/{端点ID}/cmd` | `deriveKey(**端点**配对码, '{端点ID}\|cmd')` |
| 端点 → 控制器 | `sonicshield/v1/{端点ID}/evt` | `deriveKey(**控制器**配对码, '{控制器ID}\|evt')` |

所以探针**必须同时持有两个身份**：用**端点**的配对码发命令，
用**自己**的配对码解回执。第一版探针用自身身份派生**命令**密钥 →
与端点的解密密钥永不相等 → 端点 `decode` 返回 null 并静默 return，
命令**从未被处理**；而当时把"evt 上出现任意密文"当作通过标准，
端点每 60s 的心跳恰好能满足它 → **工具给出假的"全链路闭环"**。

### 8.2 用法

```bash
dart run tool/rc_probe.dart \
  endpoint=<16位端点ID> endpointcode=<8位端点配对码> \
  selfid=<16位探针ID> selfcode=<8位探针配对码> \
  [broker=broker.emqx.io] [probe=ping,status|crud] [onlinewait=秒]
```

参数用 `key=value`（无 `--` 前缀）—— `dart run` 会吞掉连字符开头的参数。

### 8.3 探针集

| `probe=` | 命令 | 期望回执 |
|---|---|---|
| `ping` | `ping` | `rc.pong` |
| `status` | `status.get` | `rc.status` |
| `tasks` | `task.list` | `rc.tasks` |
| `assets` | `asset.list` | `rc.assets` |
| `presets` | `preset.list` | `rc.presets` |
| `device` | `device.status` | `rc.device` |
| `logs` | `logs.recent` | `rc.logs` |
| `sound` | `sound.play`（**不点名**音源） | `rc.ack` |
| `crud` | 8 步序列（见 8.4） | — |

### 8.4 CRUD 序列（`probe=crud`）

远程任务增 / 查 / 计划物化 / 改 / 删 / 清理，共 8 步：

1. `task.upsert` 正午（12:30）→ 期望 `rc.task` + `rc.ack`，且 `ack.data` 里 **`planned ≥ 1`**；
2. `task.list` 含该任务；
3. `status.get` → **`pendingCount ≥ 1`**（走 `pendingWithin` / `pendingCountAfter` 的**查库路径**）；
4. 改成免打扰内时刻（03:30，默认免打扰 22:00–07:00）+ `quietPolicy=skip`
   → 端点应**如实**回 `planned=0` 且 `pendingCount` 归零；
5. 改回正午 → `planned ≥ 1` 且 `pendingCount ≥ 1`（**重建真的发生**）；
6. `task.toggle` 停用；7. `task.delete` 删除；8. 列表不含它且 `pendingCount` 归零。

> 第 4 步是**刻意**的负向对照：第一版探针把任务设在 03:30，
> 得到 `planned=0` 时一度被误判为"远程建的任务不会物化"。
> 实际是 `QuietPolicy.skip` 按设计丢弃免打扰内的时刻
> （`ScheduleEngine._applyQuiet`）。**红灯先怀疑测量与阈值。**

### 8.5 通过判据

回执必须同时满足：**① 解密成功**（用探针自己的 evt 密钥）+
**② 类型等于期望** + **③ `payload.for` 与命令 id 一致**（无 `for` 的回执除外）。
`rc.heartbeat` 被**显式剔除**（它是周期信号，不是回执）。
失败时打印"看到多少密文 / 多少心跳 / 多少解密失败"，用于区分
「端点离线」与「密钥不匹配」。

### 8.6 宿主机锁（`test/rc_probe_keys_test.dart`，16 例）

不需要 broker、不需要设备即可断言"探针发的命令端点能解"：
密钥对称性 ×3、端到端往返 ×3（含 AAD 主题绑定）、
**旧写法必须失败 ×2**（否则这组锁恒真）、探针判据源码契约 ×5、
CRUD 载荷 ↔ 领域模型一致性 ×3。

> ⚠️ 探针**不能** import `lib/domain/models/*`：`trigger.dart` 依赖 `dart:ui`，
> 纯 Dart VM（`dart run`）会报 `Dart library 'dart:ui' is not available`。
> 故 CRUD 载荷里的枚举名用字面量，并由上面的宿主机锁逐条对齐。
