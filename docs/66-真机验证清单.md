## 1. 震动：静音/勿扰下是否真响

**代码层已做**：固定节奏链路 `NativeBridgePlugin.kt` 的 `vibrate` 分支读 `useAlarmUsage`，
`background_engine.dart` 本机自排任务经 `RemoteParity` 判定后传 `true`（走 `USAGE_ALARM`），
与 R93 的随机/持续振动策略对齐。

| 步骤 | 操作 | 抓取 | 预期值 / 判据 |
|---|---|---|---|
| V1 | 手机切静音（音量键压到 0）+ 开勿扰 | `adb shell settings get global zen_mode` | 返回非 0（勿扰生效） |
| V2 | 建一个本机固定节奏振动任务，设为立即/下一分钟触发 | `adb logcat -s flutter:V` | 见到 `vibrate` 调用且 `useAlarmUsage=true` |
| V3 | 到点观察机身 | `adb shell dumpsys vibrator` | 有 `Vibration` 记录；`usage=USAGE_ALARM`（不是 NOTIFICATION） |
| V4 | 手动触发远程下发的振动指令 | 同上 | 依老板 R105 裁决「远程=本机」，远程同样可穿勿扰 |

**故障定位**：若 V3 无记录 → `NativeBridgePlugin.kt` 的 `vibrateWaveform` 未走到；
若 `usage=NOTIFICATION` → `useAlarmUsage` 未透传到原生；若日志显示 `hasVibrator=false` →
桥异常被折叠（见 `vibrate_caps.dart`），查原生 MethodChannel 返回。

## 2. 后台音效：是否被 ducking / OEM 电池策略杀死

**代码层已做**：`playback_service.dart` 的 `_abandonAudioFocus` 有引用计数守卫，
最后一路播放结束才 `setActive(false)`；每路播放器独立释放（R90-07）。
**已知边界**：`main.dart` 与 `background_engine.dart` 在**不同 isolate** 各持一个
`PlaybackService`，静态登记表不跨 isolate —— 宿主无法验证焦点归属，须实机取证。

| 步骤 | 操作 | 抓取 | 预期值 / 判据 |
|---|---|---|---|
| A1 | 后台引擎运行中，用系统音乐 App 播放音乐 | `adb shell dumpsys audio \| grep -A20 "Player"` | 本应用播放时音乐 `ducked`，播完恢复（不永久偏低） |
| A2 | 触发一次定时音效，播完继续观察音乐 | `adb logcat -s flutter:V` | 见到 `_abandonAudioFocus` 对应日志；焦点状态回到音乐 App |
| A3 | 锁屏 + Doze 30 分钟后触发任务 | `adb shell dumpsys deviceidle` + `dumpsys audio` | 音效仍响（常驻唤醒锁 + mediaPlayback 前台服务类型生效） |
| A4 | 同场景对比另一 OEM 机型（若可用） | 同上 | 行为一致；不一致即 OEM 电池策略差异，非代码问题 |

**故障定位**：音乐永久偏低 → `setActive(false)` 未被调用（查引用计数是否归零）；
音效在 Doze 后不响 → 唤醒锁/前台服务类型被系统回收（查 `docs/05` 保活链）。

## 3. 通话卡顿：AEC/NS/AGC 与码率

**代码层已做**：`call_media_profile.dart` 新增 `audioConstraintsFor()` 单一真源，
显式声明 `echoCancellation` / `noiseSuppression` / `autoGainControl`；
`call_service.dart` 与 `multi_call_service.dart` 的裸 `audio: true` 均改走该真源。
档位表已按并发路数降码率/帧率/分辨率。

| 步骤 | 操作 | 抓取 | 预期值 / 判据 |
|---|---|---|---|
| C1 | 两台设备建立语音通话，用手在麦克风旁制造回声 | `adb logcat -s flutter:V webrtc:V` | 对方侧无自回声（AEC 生效） |
| C2 | 开免提（本产品默认免提），重复 C1 | 同上 | 仍无回声 |
| C3 | 背景放噪声，观察对方听到的音量 | 同上 | 底噪被压、音量稳定（NS/AGC） |
| C4 | 同时建 1/2/4 路视频通话，观察本机 CPU 与流畅度 | `adb shell top -n 1 \| grep sonicshield` + `dumpsys gfxinfo` | 路数越高码率/帧率阶梯下降（600k→400k→260k→150k），不掉帧到不可用 |
| C5 | 抓 WebRTC 实际协商参数 | `adb logcat \| grep -i "setParameters\|maxBitrate"` | 档位值下发；失败有留痕（非静默） |

**故障定位**：仍有回声 → 平台未接受约束（查 `getSupportedConstraints`），
需退回原生 `AudioProcessing` 配置；4 路仍爆卡 → P2P 无 SFU 的结构上限，
需评估是否引入中心 SFU（与「无中心 + E2EE」架构冲突，属产品决策）。

## 4. 屏幕共享：MediaProjection 授权

**代码层已做**：`call_service.dart` 的 `getDisplayMedia` 分支注释自承未真机验证。
本项目用 `MediaProjection` 前台服务（`ScreenCastService`，FR-85）。

| 步骤 | 操作 | 抓取 | 预期值 / 判据 |
|---|---|---|---|
| S1 | 控制端请求远程桌面（看 + 控），被控端点「授权」 | `adb logcat -s flutter:V ScreenCast:V` | 系统弹出 MediaProjection 授权弹窗 |
| S2 | 同意授权 | `adb shell dumpsys activity services \| grep -i screencast` | 前台服务启动，有常驻可见通知 |
| S3 | 拒绝授权 | 同上 | 服务不启动，回执 `ok:false`（不静默降级为「仅看」） |
| S4 | 停止会话后，用旧 `castId` 再发 `input.*` | `adb logcat` | 一律拒绝（会话失效锁） |

**故障定位**：授权弹窗不弹 → `screenCastStart` 通道未接通；
服务被杀 → 前台服务类型/`FOREGROUND_SERVICE_MEDIA_PROJECTION` 权限缺失。
