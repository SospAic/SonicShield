# 14 · 远程遥控模块设计（v1.2）

> 能力：多端点公网遥控 —— 发送指定声音、查看/修改任务状态、
> **指令组（宏）远程执行**（动作+时延序列，立即执行/随时终止）、**对讲机**。
> 对标：Home Assistant（加密配对）、KDE Connect（设备配对+命令）、
> Tasker AutoRemote（消息通道）、Zello/微信语音（对讲）。

---

## 1. 总体架构

```
        控制器（手机A）                      端点（手机B）
   ┌──────────────────┐              ┌──────────────────────┐
   │ 远程总览页        │   MQTT/TLS   │ 端点服务（引擎隔离）   │
   │ 指令组装器        │ ───────────► │  订阅 cmd 主题        │
   │ 对讲机（按住说）   │              │  → 解密 → 分派执行    │
   │                  │ ◄─────────── │  → 事件回执/心跳      │
   └──────────────────┘   公网 Broker  └──────────────────────┘
                       （EMQX/Mosquitto，仅中转密文）

 双方角色对等：任一设备都可既当控制器又当端点（App 内开关决定当前行为）。
```

> **传输要求（C-13，第三十四轮修复）**：链路是 **MQTT over TLS 8883 + 证书链强校验**，
> 且**没有**"改用明文 / 忽略证书"的运行时开关（见 §9）。端到端加密（§4）与 TLS 是
> **两层、不可互相替代**：前者挡"broker 看内容"，后者挡"链路上篡改 / 丢弃信封"。

## 2. 主题与消息

| 主题 | 方向 | 内容 |
|---|---|---|
| `sonicshield/v1/{deviceId}/cmd` | 控制器 → 端点 | 加密命令（密文） |
| `sonicshield/v1/{deviceId}/evt` | 端点 → 控制器 | 加密事件（密文） |
| 遗嘱（LWT） | broker 代发 | `{"type":"rc.offline"}` 明文哨兵（无敏感内容；由 broker 发出，故无法端到端加密，但仍走 TLS 链路） |

命令（cmd）：`ping / status.get / sound.play / task.list / task.toggle /
task.skipNext / guard.set / logsRecent / **script.run** / **script.stop** /
**vibrate.stop** / **run.master.set**（v79）/ **ptt.voice** / device.status / camera.snap / location.get / volume.set`

事件（evt）：`rc.pong / rc.status / rc.tasks / rc.logs / rc.ack /
rc.heartbeat / rc.exec / **rc.script**（步骤级进度）/ **rc.ptt** / rc.offline /
rc.device / rc.photo / rc.location / rc.call`

> ⚠️ 命令列表里的 `location.get` **不是"点了就一定成功"**：它受端点运行时定位权限、
> 系统定位开关、后台状态三重门控，任何一步不满足都只会回 `rc.location{error:true}`
> 并写明原因（C-1，第三十四轮修复，见 §9）。`camera.snap` 同理恒降级（见 §8 注记）。

### 2.1 v1.7 新增：远程任务 CRUD（与本机任务功能对齐）

目标：远程管理端点任务，能力与本机「自动化 → 任务」对齐（docs/18 背景）。

| 命令 | payload | 回执 | 说明 |
|---|---|---|---|
| `task.get` | `{taskId}` | `rc.task {task}` | 取单条任务**完整定义** |
| `task.upsert` | `{task}` | `rc.ack` | 新建或更新（按 id 幂等），**成功后端点重新物化 occurrence** |
| `task.delete` | `{taskId}` | `rc.ack` | 删除任务及其待执行 occurrence |
| `task.runNow` | `{taskId}` | `rc.ack` + `rc.script` | 立即执行该任务的动作（转译为指令组步骤，复用执行器） |
| `asset.list` | `{limit?}` | `rc.assets {assets}` | 端点音源库（供远程任务选音源） |
| `preset.list` | `{}` | `rc.presets {categories}` | 端点预置音源分类 |

**task 线格式**：与 `Task.toRow()` 同构，但 `trigger`/`action` 用**嵌套对象**
（而非 JSON 字符串）、`enabled` 用 **bool**（而非 0/1）、`assetIds` 用数组。
转换集中在 `lib/remote/task_wire.dart`，避免领域模型承担传输职责。

> **安全**：`task.upsert` 的 task 定义来自对端，端点必须做**白名单校验**
> （触发器/动作 kind 必须可解析、数值范围夹紧、`cooldownSec`/`priority` 有上下界、
> 步数与时延上限），拒绝即回 `rc.ack ok=false`，防止对端写入畸形定义拖垮调度器。
>
> **实现要点（踩坑记录）**：夹紧必须发生在**原始 JSON 层**。
> `PlayAudioAction` 的 `assert(volumeMin <= volumeMax)`、`SoundscapeAction` 的
> `assert(tracks.length in 1..4)` 都在**构造期**求值 —— 先构造再归一化时，
> debug 下 assert 先抛出（归一化永远走不到），release 下 assert 被剥离
> （归一化成了唯一防线），两条路径行为不一致。`TaskWire._sanitizeActionMap`
> 即为此而设；`test/task_wire_test.dart` TW-20..24 为回归锁。

**物化语义**：`task.upsert` 成功后端点必须先清掉该任务的**旧 pending 计划**，
再按新定义重新物化 —— 否则改了触发器会出现"幽灵计划"仍在旧时刻响
（`OccurrenceRepository.deletePendingForTask`，保留 done/failed 审计）。

**执行语义**：`task.runNow` 的真实执行发生在**后台引擎隔离**（播放器/TTS/
原生桥的插件实例都注册在引擎侧），主 isolate 的端点服务无法直接调用。
实现走 `flutter_background_service` 通道转交，引擎执行完毕经 `rcRunResult`
回投，端点**拿到结果后**才回 `rc.ack` —— 否则会出现"回执成功但实际没出声"的
假阳性。引擎未运行时明确回 `ok=false`，不静默成功。

**向后兼容**：v1 全部命令语义不变；`task.list` 新增 `full` 选项（默认 false
保持 v1 轻量形状）；端点对未知 `type` 回 `rc.ack{ok:false, data:'未知命令'}` 并写
`skipped` 审计（**不再静默忽略** —— 静默会让控制器只能等到超时，分不清
"没收到 / 不认识 / 执行失败"）。

### 2.2 v79 新增：全局执行总开关（远程启停）

用户需求：一个支持**远程控制启动/关闭**的总开关，默认在法定休息日窗口内自动关闭
（任务默认不执行/跳过），出窗自动恢复。语义与判定真源见 docs/20 §9。

| 命令 | payload | 回执 | 权限位 | 说明 |
|---|---|---|---|---|
| `run.master.set` | `{mode: 'auto' \| 'on' \| 'off'}` | `rc.ack {ok, data}` | `script` | 设置端点「全局执行总开关」；`auto`=按法定休息日自动暂停 / `on`=强制开启 / `off`=强制关闭 |

- **容错**：缺 `mode` 或值无法识别 → 按 `auto` 处理（与端点 `RunMasterMode.parse` 同口径），
  **不**静默失败也不回滚。
- **生效路径**：写 `PrefsKeys.runMasterMode` → `BackgroundServiceManager.replan()`（失败不静默，
  写 `failed` 审计）→ 写 `action:'run.master.set'` 审计 → 回 `rc.ack`。
- **`rc.status` 只读字段扩充**：`runMasterMode` / `paused` / `inPauseWindow` / `nextTransitionAt`，
  让控制端不做本地推算即可展示"运行中 / 暂停中 / 下次切换时间"。
- **权限位 = `script`**（与 `task.toggle` / `guard.set` / `plan.apply` 同组：改写持久自动化状态）。
  ⚠️ 不登记会命中 `_ => denyAll` ⇒ 协助会话下一律被拒（失败关闭）。
- **与夜间豁免互不影响**：远程**仍不得**写 `PrefsKeys.quietExemptMaster`（docs/08 §4.2 红线，
  `QE-13/14/15/20/21` 源码扫描锁）；`run_master_mode` 是**另一个**开关。

## 3. 指令组（宏）—— 组装与执行

### 3.1 步骤元素（RcStep）

| kind | 参数 | 说明 |
|---|---|---|
| play | volume / durationSec / presetCategory? | 随机播放（可限定预置分类） |
| tts | text / volume | 语音播报 |
| notify | title / body | 系统通知 |
| vibrate | pattern? / **mode?** / 模式相关参数 | 震动。**v1.9 起参数化**（见 §3.1.1） |
| record | seconds | 录音取证 |
| **delay** | seconds（0.5–600） | **时延元素**（宏节奏核心） |

约束（端点校验）：步数 ≤ 50；单步时延 ≤ 600s；时延合计 ≤ 30 分钟。

#### 3.1.1 震动步参数化（v1.9.0-alpha）

`vibrate` 步新增 `mode ∈ {fixed, random, continuous}`：

| mode | 参数 | 说明 |
|---|---|---|
| （缺省）/ `fixed` | `pattern?` | **老语义一字不变** —— 老控制器发的 `{}` 行为与 v1.8 完全一致 |
| `random` | `durationSecMin/Max`、`amplitudeMin/Max`、`gapMinMs/gapMaxMs`、`pulseMsMin/Max`、`rampUpSec`、`rampDownSec`、`dutyCycle`、`sharpness` | 随机脉冲串 |
| `continuous` | 同上 + `chunkMs` | 持续振动（分片续发） |

⚠️ **三条硬约束**（全部有"能失败"的回归锁）：

1. **未知 mode 归到 `fixed`**（`RV-02`）—— 这是**老协议的唯一语义**，不是"降级"。
2. **随机/持续振动绝不退回固定节奏**（`RV-15` 穷举）：端点没有 `vibrateActionHandler`
   时该步记 **`skipped` + 审计**，而不是"随便震一下"。静默换成另一种振动 = 用户以为
   设了 10 分钟持续振动、实际只震了一下。
3. **入站 `respectDnd` 强制 `true`**（`RV-06`）：`respectDnd=false` 会让原生改用
   `USAGE_ALARM` 即**穿透系统勿扰** —— 允许对端打开等于绕过本机合规护栏（docs/08 §2）。

振动步时长**计入**指令组 30 分钟总预算（此前只统计 `delay`，`RV-08` 锁定）。

**表单与执行器唯一真源**：字段规格表 `rcVibrateFields`（`lib/remote/rc_script.dart`）
同时驱动控制器 UI 表单与端点参数夹紧；`RV-11` / `RV-12` 断言"规格键 == 模型 `toJson()` 键"。

#### 3.1.2 全局停止：`vibrate.stop`（v1.9.0-alpha）

| 命令 | payload | 回执 | 说明 |
|---|---|---|---|
| `vibrate.stop` | `{}` | `rc.ack` | 停止端点**全部**进行中的振动（幂等） |

权限位 = `vibrate`（**能震的才能停**）：让没有振动权限的对端停掉用户自己的报警振动
同样不可接受。实现上**两步走**：引擎隔离内 `vibrateStop` + `NativeBridge.vibrateStop()`
兜底（引擎未运行时也要真的停）。⚠️ 回执**刻意不返回"停了几条"** —— 活跃表在引擎
隔离内，主 isolate 读不到；编造一个数字比不报更糟。

### 3.2 执行语义（端点）

1. 收到 script.run → 校验 → **立即执行**；
2. 双通道用户可见性：
   - heads-up 弹窗：「收到远程指令组 · 来自 X · 时间」；
   - 常驻通知栏卡片：发送方/发送时间/步骤进度（n/N）+ **【终止执行】按钮**；
3. 步骤级事件回执 `rc.script {state:running, stepIndex}`；
4. 终止：用户点通知按钮（本地）或控制器发 `script.stop`（远程）→
   取消令牌：delay 立即中断、播放立即停止 → 通知更新「已终止」；
5. 完成/终止后通知 **3 秒自动清除**；全程写 exec_logs（source=remote）。

### 3.3 组装器（控制器 UI）

- 步骤添加 chips（6 类）、点击编辑参数、上移/下移排序、删除；
- 汇编校验（空/超步数/超时延）→ 一键「发送并立即执行」；
- 支持从本机任务**反向导出**为宏草稿（ScriptDraft.fromTaskJson）。

## 4. 安全设计

| 层 | 措施 |
|---|---|
| 配对 | 8 位配对码（Crockford Base32，≈40bit）作为共享秘密，人工输入确认 |
| 密钥 | HKDF-SHA256 派生（context 绑定端点 ID + 方向 cmd/evt），每配对每方向独立 AES-256 密钥 |
| **内容加密（端到端）** | AES-256-GCM（随机 nonce + MAC），broker 只见密文 |
| **链路加密（传输层）** | **MQTT over TLS 8883**，证书链对默认信任根强校验，**fail-closed**、无忽略证书回调（C-13，§9） |
| AAD | 绑定主题（防跨主题移植密文） |
| 重放 | 时间窗 ±90s + 消息 ID 去重（10 分钟滚动表） |
| 可用性 | LWT 离线哨兵、60s 心跳、自动重连 |
| 授权 | 遥控默认关闭；仅与显式配对设备互通；接收端全程可见可终止 |
| 撤销 | `removePaired`（拒**下一条**命令）**＋** `onPeerRevoked`（立即清**在途**指令组 / 通话，§9） |

## 5. 对讲机（v1 整段模式）

- 控制端：按住说话（最长 60s，AAC）→ 松开自动整段加密上传
  （payload 内 base64，上限 200KB 内）；滑动取消；
- 端点端：落盘 → heads-up「对讲 · 来自 X」→ 自动播放 → `rc.ptt` 回执 → 审计；
- v2 路线：Opus 流式分片（250ms chunk + 序号乱序重排），Zello 式实时。

## 6. Broker 建议

| 场景 | 建议 |
|---|---|
| 快速体验 | `broker.emqx.io`（公共演示节点，仅限测试，含隐私提示；走其 **TLS 8883** 端点） |
| 个人自用 | 自建 Mosquitto（VPS）+ TLS 8883，证书须由**受信 CA 签发**（C-13 后 TLS 非可选项，§9） |
| 家庭/团队 | EMQX Cloud / NanoMQ；启用 client 证书则再加一层 |

默认关闭、显式开启；开启即提示「公共节点仅限测试」。更换 broker 无需重配对
（配对秘密与 broker 无关）。

> **C-13 约束（第三十四轮）**：客户端**只**连 8883，并对证书链做默认信任根校验；
> 自建 broker 若用自签证书，握手会直接失败（这是**有意**的 fail-closed，不是 bug）。
> 工程**不提供**"忽略证书 / 回落明文"开关，也没有指纹固定（§9 诚实边界）。

## 7.5 安全决策：「免同意控制」不予实现（2026-09-14）

需求评估：技术上可行，但未经对端同意控制他人设备属未授权访问
（多数辖区刑事犯罪），违反 docs/08 红线，**不予实现**。
合法替代：**二维码扫码配对**（物理在场即强同意证明，比手输配对码
更便捷）+ 已配对设备自动信任（现状）。列入 v1.5（§7 增补）。

## 9. 传输层与权限：C-13 / C-1 修复（第三十四轮 · 2026-09-24 续）

> 本节记录第三十四轮对 **C-13（明文 MQTT）**、**C-1（定位权限缺失）** 两个 P0 的修复，
> 外加 **P1 配对撤销在途清场**、**P2 协议注释漂移（C-9）** 与 **iOS 权限文案（P1）**。
> 缺口登记见 `docs/22 §3`（其中 `docs/22:266` 明确记录了修前状态：
> "代码注释与 docs/14 称传输为「MQTT（TLS）」—— 实际 1883 明文（缺口 C-13）"）。

### 9.1 变更表（改前 → 改后 → 为什么）

| 项 | 改前 | 改后 | 为什么 |
|---|---|---|---|
| **传输端口** | `_connect()` 构造 `MqttServerClient.withPort(broker, deviceId, 1883) ..port = 1883` —— **明文** | `withPort(store.broker, deviceId, RemoteStore.defaultBrokerPort) ..port = RemoteStore.defaultBrokerPort ..secure = true`，`defaultBrokerPort == 8883` | 明文链路可被**篡改/丢弃**（见 §9.2） |
| **证书校验** | 无 TLS | **故意不设** `onBadCertificate`；证书链对 `SecurityContext.defaultContext`（默认信任根）校验 | 回调为 null 时 Dart 对无效/自签证书**直接握手失败** → fail-closed（§9.3） |
| **定位权限（Android）** | 清单**未**声明 `ACCESS_*_LOCATION`，`Geolocator.getCurrentPosition` 必抛 → 恒失败 | 声明 `ACCESS_COARSE_LOCATION` + `ACCESS_FINE_LOCATION`；`_sendLocation` 增**三步门控** | 命令/UI/文档都在、实际恒失败（C-1，§9.5） |
| **配对撤销** | `removePaired` 只删列表 + `decideRcAdmission` 只拒**下一条**命令 → 已在跑的指令组/通话继续 | 新增 `RcEndpointService.onPeerRevoked(deviceId)`，两处撤销入口调用，**立即**停该设备的在途作业 | "列表里没有它了、它还在控制本机"（§9.6） |
| **协议注释（C-9）** | `protocol.dart` 中 `ping/status.get/camera.snap/location.get/rc.photo/rc.location` 注释与实现不符 | 按**端点实现**改正（回执载荷、camera.snap 恒降级） | 注释漂移会把"没做"读成"做了" |
| **iOS 权限文案（P1）** | `Info.plist` 无相机/定位用途说明 | 补 `NSCameraUsageDescription` + `NSLocationWhenInUseUsageDescription` | iOS **缺键即崩溃**，不是"权限被拒"（§9.7） |

### 9.2 端到端加密 vs TLS：两层各管什么，谁也不能替代谁

- **端到端加密（AES-256-GCM，§4）** 保护**内容**：broker 只看到密文，即使 broker 被
  攻破/恶意，也读不出指令与回执。它**不**保护**元数据**——谁与谁通信（`clientId`/`from`）、
  消息长度与时序、`sonicshield/v1/{deviceId}/cmd|evt` 里的设备 ID，都在明文信道上暴露。
- **TLS 8883** 保护**链路**：证书链校验确保对端是真 broker，且链路上的中间人
  **不能篡改、丢弃、抑制**信封。重放有 90s 时间窗 + 消息 ID 去重挡着（§4），但
  **"把 `script.stop` 直接丢掉"这类抑制攻击，端到端加密毫无办法** —— 密文能被完整
  送达不代表它会被送达。这正是 TLS 不是可选项的根本原因（同 `remote_store.dart:150-157`）。

### 9.3 fail-closed 论证：为什么"不设 onBadCertificate"本身就是防线

`mqtt_client` 10.11.11 在 `secure = true` 时走
`SecureSocket.connect(..., onBadCertificate: onBadCertificate)`。本工程**故意不传**该回调：
当回调为 `null` 时，Dart 对无效/自签证书**直接判定握手失败**，连接根本建立不起来 ——
因此**没有"配了坏证书也能连"的代码路径**，这是**构造上**的 fail-closed，而非依赖运行时判断。
如果再有人加一个 `onBadCertificate: (_) => true` 来"图方便"，等于把中间人后门装回来；
回归锁 `test/rc_transport_lock_test.dart` 会把 `onBadCertificate` 的任何出现判红
（见 `endpoint_service.dart:254-266` 的现场注释）。工程**也没有**"关闭 TLS"的偏好项
（无对应 prefs key），因此不存在一条能在生产上悄悄回落到明文的路径。

### 9.4 自建 broker：TLS 是硬要求，证书须由受信 CA 签发

`docs/14 §6` 早已建议个人自用走"自建 Mosquitto（VPS）"，本轮起**不再把 TLS 当作建议**：
客户端只连 8883 且做默认信任根校验，自建 broker **必须持有受信 CA 签发的证书**；
用自签证书会让握手直接失败（§9.3 的 fail-closed，是设计而非 bug）。
**不做指纹固定**（pin），也**不做**"跳过校验"的开关。

### 9.5 定位 `location.get`：三步门控与后台限制

`_sendLocation`（`endpoint_service.dart:1110-1153`）把一次定位交给**纯函数**
`acquireLocationOnce(...)`（`endpoint_service.dart:2433`）执行，拆成**三步**，每步独立留痕，
且三步**都不做任何绕过**：

1. `locationPermissionGate()` —— 运行时申请（`permission_handler` 的
   `Permission.locationWhenInUse`）；**被拒**或**永久拒绝**均返回 false 且不再弹框，
   **绝不静默降级成模糊定位**；
2. `locationServiceEnabled()` —— `Geolocator.isLocationServiceEnabled`（系统定位开关）；
3. `locationFix()` —— `Geolocator.getCurrentPosition(accuracy: medium)`。

三个 seam 都是**可注入函数**，默认实现即生产路径；抽出来是为了宿主测试能断言"权限被拒时
**不该**调用 Geolocator"这类**顺序性**约束（`flutter test` 无平台插件，真调用只会抛
`MissingPluginException`，反而掩盖分支逻辑）。任何一步失败都汇入同一个 `fail()`：
写一条 `status:'failed'` 审计（每步原因不同）并回 `rc.location{for, lat:null, lng:null,
error:true}`。

> **诚实边界（背景定位不支持）**：本轮**刻意没有**加入 `ACCESS_BACKGROUND_LOCATION`
> 与 `FOREGROUND_SERVICE_LOCATION`，前台服务声明类型仍是 `mediaPlayback|dataSync`
> （不含 `location`）。**后果**：Android 14+ 上若命令到达时端点 App 处于**后台**，
> 系统会拒绝这次定位，端点回**诚实的** `error:true`。**前台可用**。
> **根因定位（更精确）**：后台被拒的直接原因是前台服务的 `foregroundServiceType`
> **未含 `location`**（现为 `mediaPlayback|dataSync`）——这是**类型位缺失**，而**不只是**
> "权限没给"；即便拿到 `ACCESS_FINE_LOCATION`，缺 `location` 类型位的前台服务在后台
> 仍拿不到位置。该缺陷已**独立登记为 C-1b**（登记注记见
> `android/app/src/main/AndroidManifest.xml:35`）。
> 让后台定位可用是**独立的产品/合规决策**（要改 FGS 类型位、并触发 Play
> "始终允许"政策流程），**没有**夹带进本轮 P0 修复 —— 列为**待办**。
>
> 另注：`location` 是**危险权限**，必须由端点上的人在系统弹窗里点"允许"；
> 控制端能做的只是**请求**，**永远不能替端点决定**（项目红线：docs/08 隐蔽采集）。

### 9.6 配对撤销：`removePaired` 之外的在途清场（P1）

`removePaired` + `decideRcAdmission` 只拦**下一条**入站命令；**撤销之前**就已经跑起来的
作业，一条也拦不住：一个 30 分钟的 `script.run`（可能正在放音/录音）会跑到自然结束；
一通 `call.invite` 会继续占着摄像头与麦克风。而用户点"删除/取消配对"的语义是**立即断开**。

`RcEndpointService.onPeerRevoked(deviceId)`（`endpoint_service.dart:214-247`）补上这一半：
- **只清该 deviceId 名下**的在途作业 —— 停指令组靠新增的 `_activeScriptOwner`
  （在 `run()` **之前**落、结束即清空，关掉"已在跑但 owner 仍为 null"的窗口期）；
  挂断通话靠 `CallService.peerDeviceId`；
- 两处撤销入口都调用（**顺序：先出配对表，再清在途**，反了会出现"在途已停、窗口期内又
  下发一条新命令"）：`device_list_screen.dart:127-132`（「我的设备」删除）与
  `remote_screen.dart:365-368`（取消配对按钮）；
- **只在实际停掉了东西时**写一条 `action:'pair.revoke'` 审计；无在途作业则什么都不做、
  不写噪声日志。幂等，可重复调用。

### 9.7 iOS 跨平台不对称：缺权限在 Android 是"回 error"，在 iOS 是"崩溃"

`ios/Runner/Info.plist` 本轮补上 `NSCameraUsageDescription`（`:57-58`）与
`NSLocationWhenInUseUsageDescription`（`:59-60`）。**必须记住的差异**：
Android 上缺某权限最多是该命令回 `error`；**iOS 上缺对应 UsageDescription 键，TCC 会在
弹窗前先读 plist，读不到键即抛 `NSInvalidArgumentException` —— 整个应用被打挂**。
这是跨平台行为差异里**最容易被忽略、后果最重**的一类（同 `Info.plist:48-56` 的注释）。

## 10. 连接方案与节点选择（第八十二轮 · 2026-10-11）

> 本节回应「远程连接页支持下拉切换节点 + 一键测速，且把调研出的多种连接方案落地可选」。
> 落地前现状：远程设置页只有 **1 个**默认 broker（`broker.emqx.io`）+ 一个「自定义主机」输入框，
> **没有**候选节点清单、**没有**测速、**没有**传输方案选择；通话 STUN 是写死的固定列表、不可切换。

### 10.1 连接方案（`RcTransport`，三选一）

| 方案 | 端口 | 传输 | 取舍 |
|---|---|---|---|
| `tls`（默认） | 8883 | MQTT over TCP + TLS | 现状主路径；证书链走默认信任根（§9，fail-closed） |
| `wss` | 8084 | MQTT over WebSocket + TLS | 封 TCP 的企业网 / 酒店 Wi-Fi 更易穿透；**仍走 TLS** |
| `quic` | 14567 | MQTT over QUIC（UDP） | 0-RTT、弱网 / 切网不断连；⚠️ **Dart `mqtt_client` 不支持 QUIC** ⇒ 选它**回落 TLS** 并在 UI **明示**（不静默） |

- 三方案**都** `secure = true`：`wss` 走 `useWebSocket`、端口 `8084`；`quic` 回落 `tls`。
  工程**不提供**明文回落开关（与 §9 的 C-13 纪律一致）。
- 唯一构造点仍在 `lib/remote/endpoint_service.dart` `_connect()`（TL-09 只允许一处构造）。

### 10.2 节点目录（`lib/remote/node_catalog.dart`）

- **MQTT 节点**：公共演示（`broker.emqx.io` / **国内** `broker-cn.emqx.io`）+ 自建条目 +

### 10.3 一键测速（`NodeSpeedTest`）
