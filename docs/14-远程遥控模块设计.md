# 14 · 远程遥控模块设计（v1.2）

> 能力：多端点公网遥控 —— 发送指定声音、查看/修改任务状态、
> **指令组（宏）远程执行**（动作+时延序列，立即执行/随时终止）、**对讲机**。
> 对标：Home Assistant（加密配对）、KDE Connect（设备配对+命令）、
> Tasker AutoRemote（消息通道）、Zello/微信语音（对讲）。

---

## 1. 总体架构

```
        控制器（手机A）                      端点（手机B）
   ┌──────────────────┐              ┌──────────────────────┐
   │ 远程总览页        │   MQTT/TLS   │ 端点服务（引擎隔离）   │
   │ 指令组装器        │ ───────────► │  订阅 cmd 主题        │
   │ 对讲机（按住说）   │              │  → 解密 → 分派执行    │
   │                  │ ◄─────────── │  → 事件回执/心跳      │
   └──────────────────┘   公网 Broker  └──────────────────────┘
                          （EMQX/Mosquitto，仅中转密文）

 双方角色对等：任一设备都可既当控制器又当端点（App 内开关决定当前行为）。
```

## 2. 主题与消息

| 主题 | 方向 | 内容 |
|---|---|---|
| `sonicshield/v1/{deviceId}/cmd` | 控制器 → 端点 | 加密命令（密文） |
| `sonicshield/v1/{deviceId}/evt` | 端点 → 控制器 | 加密事件（密文） |
| 遗嘱（LWT） | broker 代发 | `{"type":"rc.offline"}` 明文哨兵（无敏感内容） |

命令（cmd）：`ping / status.get / sound.play / task.list / task.toggle /
task.skipNext / guard.set / logsRecent / **script.run** / **script.stop** /
**ptt.voice**`

事件（evt）：`rc.pong / rc.status / rc.tasks / rc.logs / rc.ack /
rc.heartbeat / rc.exec / **rc.script**（步骤级进度）/ **rc.ptt** / rc.offline`

## 3. 指令组（宏）—— 组装与执行

### 3.1 步骤元素（RcStep）

| kind | 参数 | 说明 |
|---|---|---|
| play | volume / durationSec / presetCategory? | 随机播放（可限定预置分类） |
| tts | text / volume | 语音播报 |
| notify | title / body | 系统通知 |
| vibrate | pattern? | 震动 |
| record | seconds | 录音取证 |
| **delay** | seconds（0.5–600） | **时延元素**（宏节奏核心） |

约束（端点校验）：步数 ≤ 50；单步时延 ≤ 600s；时延合计 ≤ 30 分钟。

### 3.2 执行语义（端点）

1. 收到 script.run → 校验 → **立即执行**；
2. 双通道用户可见性：
   - heads-up 弹窗：「收到远程指令组 · 来自 X · 时间」；
   - 常驻通知栏卡片：发送方/发送时间/步骤进度（n/N）+ **【终止执行】按钮**；
3. 步骤级事件回执 `rc.script {state:running, stepIndex}`；
4. 终止：用户点通知按钮（本地）或控制器发 `script.stop`（远程）→
   取消令牌：delay 立即中断、播放立即停止 → 通知更新「已终止」；
5. 完成/终止后通知 **3 秒自动清除**；全程写 exec_logs（source=remote）。

### 3.3 组装器（控制器 UI）

- 步骤添加 chips（6 类）、点击编辑参数、上移/下移排序、删除；
- 汇编校验（空/超步数/超时延）→ 一键「发送并立即执行」；
- 支持从本机任务**反向导出**为宏草稿（ScriptDraft.fromTaskJson）。

## 4. 安全设计

| 层 | 措施 |
|---|---|
| 配对 | 8 位配对码（Crockford Base32，≈40bit）作为共享秘密，人工输入确认 |
| 密钥 | HKDF-SHA256 派生（context 绑定端点 ID + 方向 cmd/evt），每配对每方向独立 AES-256 密钥 |
| 传输 | AES-256-GCM（随机 nonce + MAC），broker 只见密文 |
| AAD | 绑定主题（防跨主题移植密文） |
| 重放 | 时间窗 ±90s + 消息 ID 去重（10 分钟滚动表） |
| 可用性 | LWT 离线哨兵、60s 心跳、自动重连 |
| 授权 | 遥控默认关闭；仅与显式配对设备互通；接收端全程可见可终止 |

## 5. 对讲机（v1 整段模式）

- 控制端：按住说话（最长 60s，AAC）→ 松开自动整段加密上传
  （payload 内 base64，上限 200KB 内）；滑动取消；
- 端点端：落盘 → heads-up「对讲 · 来自 X」→ 自动播放 → `rc.ptt` 回执 → 审计；
- v2 路线：Opus 流式分片（250ms chunk + 序号乱序重排），Zello 式实时。

## 6. Broker 建议

| 场景 | 建议 |
|---|---|
| 快速体验 | `broker.emqx.io`（公共演示节点，仅限测试，含隐私提示） |
| 个人自用 | 自建 Mosquitto（VPS）+ TLS 8883 |
| 家庭/团队 | EMQX Cloud / NanoMQ；启用 client 证书则再加一层 |

默认关闭、显式开启；开启即提示「公共节点仅限测试」。更换 broker 无需重配对
（配对秘密与 broker 无关）。

## 7.5 安全决策：「免同意控制」不予实现（2026-09-14）

需求评估：技术上可行，但未经对端同意控制他人设备属未授权访问
（多数辖区刑事犯罪），违反 docs/08 红线，**不予实现**。
合法替代：**二维码扫码配对**（物理在场即强同意证明，比手输配对码
更便捷）+ 已配对设备自动信任（现状）。列入 v1.5（§7 增补）。

| `lib/remote/remote_store.dart` | 配对端点与身份持久化 |
| `lib/features/remote/remote_screen.dart` | 远程总览页 |
| `lib/features/remote/script_builder_screen.dart` | 指令组装器 |
