# 14 · 远程遥控模块设计（v1.2）

> 能力：多端点公网遥控 —— 发送指定声音、查看/修改任务状态、
> **指令组（宏）远程执行**（动作+时延序列，立即执行/随时终止）、**对讲机**。
> 对标：Home Assistant（加密配对）、KDE Connect（设备配对+命令）、
> Tasker AutoRemote（消息通道）、Zello/微信语音（对讲）。

---

## 1. 总体架构

```
        控制器（手机A）                      端点（手机B）
   ┌──────────────────┐              ┌──────────────────────┐
   │ 远程总览页        │   MQTT/TLS   │ 端点服务（引擎隔离）   │
   │ 指令组装器        │ ───────────► │  订阅 cmd 主题        │
   │ 对讲机（按住说）   │              │  → 解密 → 分派执行    │
   │                  │ ◄─────────── │  → 事件回执/心跳      │
   └──────────────────┘   公网 Broker  └──────────────────────┘
                          （EMQX/Mosquitto，仅中转密文）

 双方角色对等：任一设备都可既当控制器又当端点（App 内开关决定当前行为）。
```

## 2. 主题与消息

| 主题 | 方向 | 内容 |
|---|---|---|
| `sonicshield/v1/{deviceId}/cmd` | 控制器 → 端点 | 加密命令（密文） |
| `sonicshield/v1/{deviceId}/evt` | 端点 → 控制器 | 加密事件（密文） |
| 遗嘱（LWT） | broker 代发 | `{"type":"rc.offline"}` 明文哨兵（无敏感内容） |

命令（cmd）：`ping / status.get / sound.play / task.list / task.toggle /
task.skipNext / guard.set / logsRecent / **script.run** / **script.stop** /
**vibrate.stop** / **ptt.voice** / device.status / camera.snap / location.get / volume.set`

事件（evt）：`rc.pong / rc.status / rc.tasks / rc.logs / rc.ack /
rc.heartbeat / rc.exec / **rc.script**（步骤级进度）/ **rc.ptt** / rc.offline /
rc.device / rc.photo / rc.location / rc.call`

### 2.1 v1.7 新增：远程任务 CRUD（与本机任务功能对齐）

目标：远程管理端点任务，能力与本机「自动化 → 任务」对齐（docs/18 背景）。

| 命令 | payload | 回执 | 说明 |
|---|---|---|---|
| `task.get` | `{taskId}` | `rc.task {task}` | 取单条任务**完整定义** |
| `task.upsert` | `{task}` | `rc.ack` | 新建或更新（按 id 幂等），**成功后端点重新物化 occurrence** |
| `task.delete` | `{taskId}` | `rc.ack` | 删除任务及其待执行 occurrence |
| `task.runNow` | `{taskId}` | `rc.ack` + `rc.script` | 立即执行该任务的动作（转译为指令组步骤，复用执行器） |
| `asset.list` | `{limit?}` | `rc.assets {assets}` | 端点音源库（供远程任务选音源） |
| `preset.list` | `{}` | `rc.presets {categories}` | 端点预置音源分类 |

**task 线格式**：与 `Task.toRow()` 同构，但 `trigger`/`action` 用**嵌套对象**
（而非 JSON 字符串）、`enabled` 用 **bool**（而非 0/1）、`assetIds` 用数组。
转换集中在 `lib/remote/task_wire.dart`，避免领域模型承担传输职责。

> **安全**：`task.upsert` 的 task 定义来自对端，端点必须做**白名单校验**
> （触发器/动作 kind 必须可解析、数值范围夹紧、`cooldownSec`/`priority` 有上下界、
> 步数与时延上限），拒绝即回 `rc.ack ok=false`，防止对端写入畸形定义拖垮调度器。
>
> **实现要点（踩坑记录）**：夹紧必须发生在**原始 JSON 层**。
> `PlayAudioAction` 的 `assert(volumeMin <= volumeMax)`、`SoundscapeAction` 的
> `assert(tracks.length in 1..4)` 都在**构造期**求值 —— 先构造再归一化时，
> debug 下 assert 先抛出（归一化永远走不到），release 下 assert 被剥离
> （归一化成了唯一防线），两条路径行为不一致。`TaskWire._sanitizeActionMap`
> 即为此而设；`test/task_wire_test.dart` TW-20..24 为回归锁。

**物化语义**：`task.upsert` 成功后端点必须先清掉该任务的**旧 pending 计划**，
再按新定义重新物化 —— 否则改了触发器会出现"幽灵计划"仍在旧时刻响
（`OccurrenceRepository.deletePendingForTask`，保留 done/failed 审计）。

**执行语义**：`task.runNow` 的真实执行发生在**后台引擎隔离**（播放器/TTS/
原生桥的插件实例都注册在引擎侧），主 isolate 的端点服务无法直接调用。
实现走 `flutter_background_service` 通道转交，引擎执行完毕经 `rcRunResult`
回投，端点**拿到结果后**才回 `rc.ack` —— 否则会出现"回执成功但实际没出声"的
假阳性。引擎未运行时明确回 `ok=false`，不静默成功。

**向后兼容**：v1 全部命令语义不变；`task.list` 新增 `full` 选项（默认 false
保持 v1 轻量形状）；端点对未知 `type` 静默忽略。

## 3. 指令组（宏）—— 组装与执行

### 3.1 步骤元素（RcStep）

| kind | 参数 | 说明 |
|---|---|---|
| play | volume / durationSec / presetCategory? | 随机播放（可限定预置分类） |
| tts | text / volume | 语音播报 |
| notify | title / body | 系统通知 |
| vibrate | pattern? / **mode?** / 模式相关参数 | 震动。**v1.9 起参数化**（见 §3.1.1） |
| record | seconds | 录音取证 |
| **delay** | seconds（0.5–600） | **时延元素**（宏节奏核心） |

约束（端点校验）：步数 ≤ 50；单步时延 ≤ 600s；时延合计 ≤ 30 分钟。

#### 3.1.1 震动步参数化（v1.9.0-alpha）

`vibrate` 步新增 `mode ∈ {fixed, random, continuous}`：

| mode | 参数 | 说明 |
|---|---|---|
| （缺省）/ `fixed` | `pattern?` | **老语义一字不变** —— 老控制器发的 `{}` 行为与 v1.8 完全一致 |
| `random` | `durationSecMin/Max`、`amplitudeMin/Max`、`gapMinMs/gapMaxMs`、`pulseMsMin/Max`、`rampUpSec`、`rampDownSec`、`dutyCycle`、`sharpness` | 随机脉冲串 |
| `continuous` | 同上 + `chunkMs` | 持续振动（分片续发） |

⚠️ **三条硬约束**（全部有"能失败"的回归锁）：

1. **未知 mode 归到 `fixed`**（`RV-02`）—— 这是**老协议的唯一语义**，不是"降级"。
2. **随机/持续振动绝不退回固定节奏**（`RV-15` 穷举）：端点没有 `vibrateActionHandler`
   时该步记 **`skipped` + 审计**，而不是"随便震一下"。静默换成另一种振动 = 用户以为
   设了 10 分钟持续振动、实际只震了一下。
3. **入站 `respectDnd` 强制 `true`**（`RV-06`）：`respectDnd=false` 会让原生改用
   `USAGE_ALARM` 即**穿透系统勿扰** —— 允许对端打开等于绕过本机合规护栏（docs/08 §2）。

振动步时长**计入**指令组 30 分钟总预算（此前只统计 `delay`，`RV-08` 锁定）。

**表单与执行器唯一真源**：字段规格表 `rcVibrateFields`（`lib/remote/rc_script.dart`）
同时驱动控制器 UI 表单与端点参数夹紧；`RV-11` / `RV-12` 断言"规格键 == 模型 `toJson()` 键"。

#### 3.1.2 全局停止：`vibrate.stop`（v1.9.0-alpha）

| 命令 | payload | 回执 | 说明 |
|---|---|---|---|
| `vibrate.stop` | `{}` | `rc.ack` | 停止端点**全部**进行中的振动（幂等） |

权限位 = `vibrate`（**能震的才能停**）：让没有振动权限的对端停掉用户自己的报警振动
同样不可接受。实现上**两步走**：引擎隔离内 `vibrateStop` + `NativeBridge.vibrateStop()`
兜底（引擎未运行时也要真的停）。⚠️ 回执**刻意不返回"停了几条"** —— 活跃表在引擎
隔离内，主 isolate 读不到；编造一个数字比不报更糟。

### 3.2 执行语义（端点）

1. 收到 script.run → 校验 → **立即执行**；
2. 双通道用户可见性：
   - heads-up 弹窗：「收到远程指令组 · 来自 X · 时间」；
   - 常驻通知栏卡片：发送方/发送时间/步骤进度（n/N）+ **【终止执行】按钮**；
3. 步骤级事件回执 `rc.script {state:running, stepIndex}`；
4. 终止：用户点通知按钮（本地）或控制器发 `script.stop`（远程）→
   取消令牌：delay 立即中断、播放立即停止 → 通知更新「已终止」；
5. 完成/终止后通知 **3 秒自动清除**；全程写 exec_logs（source=remote）。

### 3.3 组装器（控制器 UI）

- 步骤添加 chips（6 类）、点击编辑参数、上移/下移排序、删除；
- 汇编校验（空/超步数/超时延）→ 一键「发送并立即执行」；
- 支持从本机任务**反向导出**为宏草稿（ScriptDraft.fromTaskJson）。

## 4. 安全设计

| 层 | 措施 |
|---|---|
| 配对 | 8 位配对码（Crockford Base32，≈40bit）作为共享秘密，人工输入确认 |
| 密钥 | HKDF-SHA256 派生（context 绑定端点 ID + 方向 cmd/evt），每配对每方向独立 AES-256 密钥 |
| 传输 | AES-256-GCM（随机 nonce + MAC），broker 只见密文 |
| AAD | 绑定主题（防跨主题移植密文） |
| 重放 | 时间窗 ±90s + 消息 ID 去重（10 分钟滚动表） |
| 可用性 | LWT 离线哨兵、60s 心跳、自动重连 |
| 授权 | 遥控默认关闭；仅与显式配对设备互通；接收端全程可见可终止 |

## 5. 对讲机（v1 整段模式）

- 控制端：按住说话（最长 60s，AAC）→ 松开自动整段加密上传
  （payload 内 base64，上限 200KB 内）；滑动取消；
- 端点端：落盘 → heads-up「对讲 · 来自 X」→ 自动播放 → `rc.ptt` 回执 → 审计；
- v2 路线：Opus 流式分片（250ms chunk + 序号乱序重排），Zello 式实时。

## 6. Broker 建议

| 场景 | 建议 |
|---|---|
| 快速体验 | `broker.emqx.io`（公共演示节点，仅限测试，含隐私提示） |
| 个人自用 | 自建 Mosquitto（VPS）+ TLS 8883 |
| 家庭/团队 | EMQX Cloud / NanoMQ；启用 client 证书则再加一层 |

默认关闭、显式开启；开启即提示「公共节点仅限测试」。更换 broker 无需重配对
（配对秘密与 broker 无关）。

## 7.5 安全决策：「免同意控制」不予实现（2026-09-14）

需求评估：技术上可行，但未经对端同意控制他人设备属未授权访问
（多数辖区刑事犯罪），违反 docs/08 红线，**不予实现**。
合法替代：**二维码扫码配对**（物理在场即强同意证明，比手输配对码
更便捷）+ 已配对设备自动信任（现状）。列入 v1.5（§7 增补）。
