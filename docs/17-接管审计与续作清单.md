## 4. 代码与任务流分析

### 4.1 主调度链路（健康）

```
Task 定义 ──materialize(now, 48h)──► PlannedEntry ──幂等提交──► occurrences(pending)
   ▲                                                                    │
   │ 续算：pending < 12h                                                  │ executeDue()
   │                                                                     ▼
通道A：引擎 isolate Timer(15s) ──────────────────────────────► runAction()
通道B：AlarmWatchdogReceiver ──startForegroundService──► 引擎 ─►  Playback/TTS/Notify/Record/Vibrate
                                                                        │
                                                              exec_logs（全量审计）
```
链路自洽：occurrences 状态机保证双通道幂等，已由 61 例功能测试与单测覆盖。

### 4.2 远程链路（**断裂**）

```
控制器A                                            端点B
  subscribe  A/cmd  ✔（仅此一条）                    subscribe  B/cmd  ✔
  publish    ────────── B/cmd（密文） ─────────────► 解密 → _dispatch
                                                          │
  ✘ 无任何订阅 ◄──────── B/evt（rc.pong/rc.ack/ ─────────┘ _send() → B/evt
                          rc.status/call.answer/…）
```
**B 把回执发到 `B/evt`，而 A 只订阅了 `A/cmd` —— 回执永远收不到。**
后果：Ping 无往返、状态/任务/定位无回执、指令组无步骤进度与终止回执、
PTT 无回执、**视频通话 `call.answer` / `call.candidate` 收不到 → 永远停在 connecting**。
这解释了 HANDOVER §5「双设备互通未实测」为何始终无法推进。

### 4.3 v1.6 远程中心可达性（**孤儿**）

`git show 1a92111` 的文件清单**不含 `lib/core/router.dart`**。实测：
- `RemoteHomeScreen` / `RemoteConsoleTab` / `RemoteScriptsTab` / `PttTab`
  仅被彼此引用，**全库无第二个引用点**；
- `router.dart:44` 仍为 `GoRoute(path:'/remote', builder: … const RemoteScreen())`，
  即 v1.2 旧总览页；
- 设置页入口 `context.push('/remote')` 同样落到旧页。

→ 控制台（含 device.status / location.get / volume.set / camera.snap 按钮）
**用户永远点不到**；v1.6 的功能实质是未交付状态。
