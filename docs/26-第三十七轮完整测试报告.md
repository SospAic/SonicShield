## 三、P0 缺陷（本轮发现并闭环）

### P0-1 · 一个测试文件让整个功能层**挂死**（门禁既不是绿也不是红）

| 项 | 内容 |
|---|---|
| **现象** | `bash scripts/gates.sh` 跑到第 2 步永不结束：`flutter_tester` 存活但 **CPU 停滞在 3.3s**、`coverage/lcov.info` 时间戳不更新 ⇒ **退出码永远拿不到** |
| **定位链** | ① 对比 `_pt/` 产物与 `lcov.info` 时间戳 ⇒ 最近成功门禁早于该文件创建时间；② 有界单跑 ⇒ `TEST_RC=124`（240s 硬超时）；③ `--timeout 30s` 无效 ⇒ 卡点在 **fake-async 区**；④ 对照项目自己的测试类注释 ⇒ 命中**早已写明的硬约束** |
| **根因** | `databaseFactoryFfi` 的 SQLite 在**后台 isolate**、往返是**真实异步**；`testWidgets` 用例体运行在 `FakeAsync` 里 ⇒ 用例体内直接 `await` 库操作**永不返回**（`pumpAndSettle` 需等 **10 分钟**默认超时才吐错） |
| **为什么此前无人发现** | 该文件 23:17 新建后**从未被验证**：触发它的中继作业 `jobL5.sh` 被计划任务**单槽 `IgnoreNew` 静默吞掉** —— `l5.txt` 与 `l5.txt.done` **两个产物都不存在** |
| **影响** | 交付链**停摆**：既不是红（不会触发修复）也不是绿（不能发版） |
| **修法** | 照 `task_list_screen_test.dart` / `settings_screen_test.dart` 既有范式重写：开库放 `setUp`、用例体 DB 操作包 `tester.runAsync`、有界 `waitFor(cond)` 代替 `pumpAndSettle`、每例 `timeout: 90s`、收尾推掉 SnackBar 计时 |
| **净效应** | `lib/features/guard/guard_screen.dart` 未覆盖 **87 → 13 行**；功能层 **+10 例**；真实进度 **+74 行**；**零生产代码改动** |

**修复过程三段实测**（这就是"修好了"的证据）：

| 版本 | 结果 |
|---|---|
| 首版（09-26 23:17） | **硬超时 240s 被杀**，0 例完成（挂死） |
| 第一版修复 | 93s，`+6 -4` |
| **终版** | **3s，`+10` 全绿** |

**附带固化的 4 条宿主测试铁律**（本轮 4 次假红换来，已写进测试文件注释与 `docs/12 §71.3`）：

1. 引擎状态流必须 `StreamController.broadcast()` —— `Stream.value` 是**单订阅**流，而 `_onToggleGuard`
   会 `ref.invalidate(engineStateProvider)` ⇒ 重新订阅抛 `Bad state: Stream has already been listened to`。
2. 事件必须在**订阅建立之后**再 `add`（broadcast 不重放历史）—— 先 `add` 后 `pumpWidget` 会让状态卡
   永远停在 `LinearProgressIndicator`，两条断言**假红**。
3. 长 `ListView` 必须放大视口（`tester.view.physicalSize`）—— 默认 800×600 下编排区落在折叠区，
   `tester.tap` 因"不在视口"落空。
4. **种子数据（写库）同样必须过 `runAsync`** —— 不只"读"。
