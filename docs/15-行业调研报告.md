# 15 · 同类项目全行业调研报告

> 调研对象：与声盾 SonicShield 九大能力域相关的领先产品与开源项目
> 方法：公开资料检索（产品页/官方文档/社区讨论/开发者文章/平台政策文档）
> 日期：2026-09 ｜ 结论服务于路线图（docs/11）与版本规划

## 1. 赛道全景：声盾横跨九条赛道

```
        ┌─ 自动化引擎（Tasker/MacroDroid/Automate）
        ├─ 闹钟与提醒（Alarmy/Sleep as Android）
        ├─ 声景与助眠（Tide/Calm/Soundscape Mixer/Moodist）
声盾 ──┼─ 远程遥控与IoT（Home Assistant/KDE Connect/AutoRemote/Join）
        ├─ 对讲机（Zello/VoicePing/Fast Talkie）
        ├─ 声音事件检测（YAMNet/AudioSet/MediaPipe Audio）
        ├─ 平台后台策略（Android 16 FGS / WorkManager）
        ├─ 取证与记录（审计日志/录音链）
        └─ 跨端框架（Flutter 隔离/后台最佳实践）
```

**核心洞察**：没有一个现成产品同时覆盖「随机化调度 + 声音触发 + 远程遥控 +
取证审计」。声盾的差异化恰恰在**交叉带**；而各赛道的成熟单品各自提供了
可借鉴的领先理念与实现范式。

## 2. 分域调研

### 2.1 自动化引擎：Tasker / MacroDroid / Automate

| 维度 | 发现 |
|---|---|
| 定位分层 | Tasker（350+ 动作，进阶用户）；MacroDroid（直观宏 UI，新手）；Automate（流程图式）——**UI 复杂度分层是行业共识** |
| 触发体系 | 触发器→条件→动作的宏模型； MacroDroid 的触发器市场/社区模板 |
| 生态 | Tasker 的 AutoApps 插件体系与 TaskerNet 分享社区是其护城河 |
| 平台限制 | 均严格 Android-only；新版 Android 收紧后台后均在适配 |

**对声盾启示**
1. **触发→条件→动作三段式**值得吸收：当前任务模型有触发与动作，但缺「条件」层
   （电量/Wi-Fi/耳机/时段前置条件）——已在 v1.1-B 规划，优先级可提前；
2. **模板分享**（TaskerNet 式）：任务导出为可分享 JSON + 社区模板页，
   冷启动内容飞轮；
3. **UI 分层**：基础宏（我们的编辑器已接近 MacroDroid）+ 高级模式
   （条件嵌套）避免一步到位做 Tasker。

### 2.2 闹钟与提醒：Alarmy / Sleep as Android

| 维度 | 发现 |
|---|---|
| 极端唤醒 | Alarmy：「末日音效」等超响闹铃 + 解除任务（数学题/拍照/深蹲/条码扫描） |
| 智能唤醒 | Sleep as Android：睡眠周期追踪 + 最优窗口轻唤醒 + QR/NFC 验证码任务 |
| 渐强音量 | 两者均内置**音量渐强**（与我们 v1.1 的 rampUpSec 一致，属行业标配） |
| 随机性 | 提醒 repeat 计划较固定，**随机时间提醒仍是空位** |

**对声盾启示**
1. 渐强唤醒是行业标配 → 我们已交付 ✓；
2. **「解除任务」思路**可反向借鉴：触发动作前先验证用户在场
   （防误触/防滥用），如「长按 3 秒确认」或可配置的确认任务；
3. **随机化提醒仍是空白市场**——声盾的随机窗口/随机间隔是差异化卖点，
   应在商店文案中放大（仍需合规话术）。

### 2.3 声景与助眠：Tide / Calm / Soundscape Mixer / Moodist

| 维度 | 发现 |
|---|---|
| 混音 | Tide 与 Soundscape Mixer 的**多轨混音**是核心付费点（雨+雷+风扇叠加，独立音量） |
| 离线 | 音频缓存/下载离线播放为标配（audio caching） |
| 免费模式 | Moodist：84 种声音的**免费开源**环境音发生器（Web）证明合成/程序化路线可行 |
| 附加 | 呼吸练习、专注计时、睡眠计时器 |

**对声盾启示**
1. **多轨混音**（v1.1-A 已规划）是对标 Tide 的必备项，实现顺序应提前；
2. Moodist 验证了我们的**程序化合成路线**（零版权、小体积），
   可继续扩充合成器库而非采购采样；
3. 预置库按「场景包」组织（专注/睡眠/提醒）而非纯分类，转化率更高。

### 2.4 远程遥控与 IoT：Home Assistant / KDE Connect / AutoRemote / Join

| 维度 | 发现 |
|---|---|
| HA | MQTT v5 + Mosquitto 为骨干；**传输 TLS 为主，端到端加密非默认**——声盾的 E2EE（AES-256-GCM）超出行业基准 |
| KDE Connect | 设备配对 + 预定义远程命令（锁屏/重启/音量）；LAN 为主 |
| AutoRemote | 每设备**个人 URL**，互联网可达；命令匹配灵活；Tasker 桥梁 |
| Join | Google 账号云中转；通知跨设备同步与远程交互；Web 端推送 |

**对声盾启示**
1. 我们的**端到端加密配对模型（配对码→HKDF→AES-GCM）领先于 HA 的
   「TLS 到 broker」模式**——broker 永不见明文，应在文档与商店页强调；
2. **个人 URL/云中转**（AutoRemote/Join）体验优于「双方连同一 broker」——
   v2 可加「中继服务」选项（仍 E2EE，服务端只转发）；
3. KDE Connect 的**命令面板**（预定义命令一键执行）对应我们的
   「收藏指令组」——可加主页快捷执行卡片；
4. Join 的**通知同步/远程交互**可扩展：端点执行事件实时推送到所有
   已配对控制器（我们已有 rc.exec/rc.script 事件，方向正确）。

### 2.5 对讲机：Zello / VoicePing / Fast Talkie

| 维度 | 发现 |
|---|---|
| 规模 | Zello 1.5 亿用户、200+ 国，PTToC（蜂窝对讲）品类定义者 |
| 架构 | 服务器流式中转（非 P2P），在线 Presence、频道模型、历史回放 |
| 离线 | **离线消息服务器暂存 + 重连补发**；转写（Premium）；锁屏 PTT（Fast Talkie） |
| 限制 | 必须联网（应急场景的认知误区，官方专门澄清） |

**对声盾启示**
1. 我们 v1 的**整段模式**（微信语音式）是正确起点；Zello 的**服务器暂存 +
   重连补发**应纳入 v2：端点离线时消息保序暂存（broker retain 或自建队列）；
2. **转写**（语音→文字）是 Zello 的付费点，也适配取证场景
   （TTS/STT 均可用平台 API）；
3. **锁屏快捷 PTT**（Fast Talkie）低成本高感知，可做 v2 小组件。

### 2.6 声音事件检测：YAMNet / AudioSet / MediaPipe Audio

| 维度 | 发现 |
|---|---|
| 事实标准 | **YAMNet（MobileNet v1 骨干，AudioSet 521 类）是移动端声音事件分类事实标准** |
| 官方支持 | Google AI Edge/MediaPipe Audio Classifier 第一方支持 YAMNet；TFLite 转换路径成熟 |
| 部署 | 从波形直接推理，边缘部署高效；int8 量化 ~4MB |

**对声盾启示**
1. v2 的 YAMNet 路线（docs/06 §6）技术风险低：**MediaPipe Audio Classifier
   可直接替代自写 TFLite 胶水**，接口按「白名单类别 + 置信度阈值」设计；
2. 与现有 v1 能量阈值管线叠加：VAD 前置过滤（省电）→ YAMNet 精分类
   （减误报）→ 任务执行，与 docs/06 设计完全一致；
3. 类别白名单应对齐 AudioSet 标签（shout/speech/dog/knock/music…），
   UI 暴露为「守护对象」选择。

### 2.7 平台后台策略：Android 16 / WorkManager / Timer 可靠性

| 维度 | 发现 |
|---|---|
| FGS | Android 16 延续收紧：后台启动 FGS 受限、类型强制、BOOT_COMPLETED 启动受限类型被 Play 检查标记 |
| 麦克风 | 后台 mic FGS 启动被禁（前台启动例外）；后台中活动服务也可能丢麦克风 |
| Timer | **Timer/Timer.periodic 在后台不可靠是社区公认**（Doze/挂起 ~1 分钟内冻结）——印证我们「双通道 + 原生闹钟」架构的必要性 |
| 迁移 | 可延迟工作官方推荐 WorkManager/JobScheduler（最小周期 15 分钟） |
| 插件 | Capacitor 等插件在 Android 16 的 BOOT_COMPLETED FGS 启动已报错误 |

**对声盾启示**
1. 我们的架构与官方推荐完全对齐：FGS（mediaPlayback，用户可见）承载
   精确调度 + 原生精确闹钟（豁免 Doze）+ WorkManager 类思路的滚动计划；
2. **BUG-011 的 runZonedGuarded 修复**与社区「Timer 后台冻结」问题一致，
   双通道互备是正确解；
3. BOOT_COMPLETED 限制应保持现状（仅恢复 mediaPlayback 类型，不碰
   mic 类型）——与 Play 政策扫描兼容；
4. M4 真机矩阵是必须的（模拟器无法覆盖 OEM 行为）。

### 2.8 取证与审计

横切发现：法律向录音类应用的共性是**时间戳链、文件完整性（哈希）、
防篡改导出**。声盾现有 exec_logs 审计 + 时间戳，可补：文件 SHA-256 入库、
导出包签名摘要——提升证据效力（合规文档 docs/08 同步）。

### 2.9 跨端框架：Flutter 隔离与后台

官方文档确认长驻 isolate 模式正确；社区一致结论：
**前台服务 + isolate 是计时关键型任务的唯一可靠组合**；
WorkManager 仅适合可延迟任务（15 分钟下限）。与声盾现状一致。

## 3. 领先理念提炼（八条）

1. **分层复杂度**（Tasker vs MacroDroid）：同一引擎服务新手与高手两档 UI；
2. **宏的节奏感**（Alarmy 任务、AutoRemote 命令匹配）：动作+条件+确认的
   序列化表达能力比单点功能更值钱；
3. **混音即产品**（Tide/Soundscape）：多轨叠加+场景包把「音效播放」
   升维成「声景创作」；
4. **E2EE 优先于传输加密**（超越 HA 基准）：隐私即卖点，尤其对
   遥控-被遥控的敏感组合；
5. **离线韧性**（Zello 暂存补发 / Soundscape 离线包）：远程与声景都应有
   断线降级路径；
6. **平台边界内创新**（Android 16 FGS）：把限制写成功能（前台类型声明、
   用户可见性、可终止性）；
7. **内容飞轮**（TaskerNet/MacroDroid 模板）：模板分享带来留存与传播；
8. **证据效力**（取证类共性）：时间戳链+完整性哈希让日志从「排障工具」
   升级为「法律资产」。

## 5. 差异化定位

```
  声景助眠（Tide）    自动化（Tasker）    远程遥控（Join）    对讲（Zello）
        │                  │                  │                │
        └──────┬───────────┴────────┬─────────┴───────┬────────┘
               │   交叉带 = 声盾护城河   │                │
               ▼                        ▼                ▼
   随机化音频调度 + 声音触发 + 取证审计 + 端到端加密遥控
   （单一竞品均无完整组合；合规护栏为额外差异）
```

传播策略：
1. 商店副标题强调「随机提醒 · 声音自动化 · 取证守护」三词组合（避开敏感词）；
2. 用「60 条合成音效零版权」讲成本与隐私故事；
3. 用「E2EE 遥控」对焦隐私敏感人群（超越 HA 基准）。
