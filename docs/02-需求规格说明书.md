# 02 · 需求规格说明书

> 依据 GB/T 8567 与 IEEE 830 风格组织；编号规则：FR-x 功能需求，NFR-x 非功能需求。
> 每条需求标注优先级（P0 必须 / P1 应该 / P2 可选）与验收标准。

---

## 1. 功能需求

### 1.1 任务管理

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-01 | 创建/编辑/删除/启停任务 | P0 | 删除任务级联清理其计划与日志入口；启停即时生效并触发重算 |
| FR-02 | 任务命名与音源池绑定 | P0 | 音源池为空时执行播放动作记失败日志并通知 |
| FR-03 | 任务列表展示触发类型、动作类型与下次触发时间 | P0 | 与后台引擎状态一致（≤1s 延迟） |

### 1.2 触发方式（对应 `TriggerType`）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-10 | **fixedOnce** 固定一次 | P0 | 到点执行一次；过期创建自动不生效 |
| FR-11 | **dailyAt** 每日定时，可选日期范围 | P0 | 视界内每天生成一条 |
| FR-12 | **weeklyAt** 每周选定星期+时刻 | P0 | ISO 星期编号 1–7，空集合拒绝保存 |
| FR-13 | **randomWindow** 随机窗口：日期范围 × 每日时间窗内随机 N 次，最短间隔约束，支持跨午夜窗口 | P0 | 见 docs/04 算法验收用例；同日计划重算结果一致 |
| FR-14 | **randomInterval** 随机间隔：[minGap, maxGap] 均匀随机推进，活动窗口与每日上限约束 | P0 | 间隔全部落在区间内；不越活动窗 |
| FR-15 | **soundTriggered** 声音触发 | P0 | 检测→冷却校验→执行；与时间计划互斥（不进时间计划表） |
| FR-16 | 免打扰命中处理策略：跳过（skip）或平移（shift）至免打扰结束点 | P0 | 边界：跨午夜窗口、结束点本身不受限 |

### 1.3 随机化（核心卖点）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-20 | 随机时刻（窗口内均匀分布，带最小间隔） | P0 | 大样本 KS 检验通过（v1 用分布抽样断言） |
| FR-21 | 随机日期范围 | P0 | 严格落在 [start, end] |
| FR-22 | 随机时长 [min, max] 秒 | P0 | 物化期确定并写入 occurrence（审计可回溯） |
| FR-23 | 随机音量 [min, max] | P0 | 同上；不超过系统硬上限 100% |
| FR-24 | 音源按权重随机挑选 | P1 | 权重为空则等概率 |
| FR-25 | **确定性随机**：seed = hash(taskId, 计划日) | P0 | 任意次重算同一计划（重启/升级不漂移）；跨任务/跨日互不相同 |

### 1.4 动作（对应 `ActionType`）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-30 | playAudio：通道 media/alarm、淡入淡出、到点停止 | P0 | alarm 通道可穿透勿扰（用户显式开启并提示合规） |
| FR-31 | tts：系统 TTS 播报 | P1 | 语言 zh-CN，音量可配 |
| FR-32 | notify：系统通知 | P0 | Android 13+ 通知权限前置 |
| FR-33 | recordEvidence：录音 N 秒存私有目录 | P0 | 文件名带 `.evidence.m4a` 标记；不进媒体库扫描 |
| FR-34 | vibrate：自定义节奏（固定模式） | P2 | **无震动能力/无振幅控制设备必须明示告知用户并留痕**（口径修正：原"静默降级"与项目通则冲突，见 docs/20 §2.3） |
| FR-35 | composite：前缀通知 + 主动作 | P1 | 通知先于播放发出 |
| FR-36 | **随机振动**：一次触发内随机脉冲串（脉冲时长/间隔/强度均随机），配合 `randomInterval` 触发实现"随机间隔的随机振动" | P1 | 全部随机量在物化期用 DPRNG 落地并写入 occurrence（可复现、可审计）；脉冲数受 `maxPulses` 约束；见 docs/20 §4.2 |
| FR-37 | **持续振动**：指定时长内连续振动，强度可在区间内随机波动，支持渐强/渐弱/占空比/锐度 | P1 | 能力降级链完整（Android16 包络 → 波形+振幅 → on/off → 旧 API），**每一级降级都明示**；见 docs/20 §4.3、§5.2 |
| FR-38 | **振动能力探测**：上报 `hasVibrator` / `hasAmplitudeControl` / 包络支持 / 最小控制点时长 | P1 | 探测结果驱动降级决策与 UI 提示条；不支持的设置项在 UI 明示失效；见 docs/20 §5.1、§11 |
| FR-39 | **夜间独立豁免**：免打扰时段可按任务显式豁免（对所有功能生效），双重开关 + 全量审计 | P2 | 主开关与任务级开关**默认均为关**；**远程命令不得开启**（入站一律丢弃该字段）；每次豁免留痕；见 docs/20 §8 |
| FR-39a | **振动失效安全**：不设时长硬上限的前提下，必须保证"任何时刻都能停" | P1 | S1 进程死即停（分片续发）/ S2 重启绝不续发 / S3 全局停止入口（本地+远程）/ S4 低电量自动停止；四条均有"能失败"的回归锁；见 docs/20 §7.2 |

### 1.8 执行条件（条件层，对应 `TaskCondition`）

任务可配置**前置条件**：全部满足才执行，任一不满足则计划标 `skipped` 并写审计。
条件层借鉴行业领先自动化工具（Tasker / MacroDroid 的条件段与约束）。

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-64 | 仅充电时执行 | P2 | 充电/满电视为满足；无电池平台视为满足 |
| FR-65 | 最低电量阈值（0–100，可选） | P2 | 低于阈值跳过，审计含具体数值 |
| FR-66 | 每日时段窗口（含跨零点） | P1 | 窗口外跳过；跨零点（如 22:00–07:00）判定正确 |
| FR-67 | 仅 Wi-Fi 下执行（可选） | P2 | 移动网络下跳过；**不新增运行时权限**（仅 normal 级 `ACCESS_NETWORK_STATE`） |
| FR-68 | **通话中不执行（默认开启）** | P0 | 通话中跳过并写审计；判定**不得申请 `READ_PHONE_STATE`**；对未配置条件的历史任务同样生效 |
| FR-69 | 条件无法判定时按"满足"处理（不静默停掉自动化） | P1 | 桥不可用（如 iOS）时自动化不被整体阻断 |

> FR-68 的设计取舍见 docs/12 §17.2：用 `AudioManager.getMode()` 判定通话，
> **零新增权限**，且对 VoIP/视频通话同样有效；默认开启是因为定时音频灌进通话
> 对双方都是干扰，且使用者无法预期。

## 2. 非功能需求

| 编号 | 类别 | 需求 | 验收标准 |
|---|---|---|---|
| NFR-01 | 可靠性 | 24h 观察窗任务执行成功率 ≥ 99% | 长跑测试（docs/09 §5） |
| NFR-02 | 可靠性 | 进程被杀后 60s 内由闹钟看门狗恢复 | `adb shell am kill` 用例 |
| NFR-03 | 性能 | 常驻内存 ≤ 150MB（引擎隔离 + UI） | dumpsys meminfo 采样 |
| NFR-04 | 性能 | 计划重算 ≤ 500ms（100 任务） | 基准测试 |
| NFR-05 | 电量 | 平衡模式后台日耗电 ≤ 3%（Pixel 基准机） | batterystats |
| NFR-06 | 兼容性 | Android 7.0 (API 24) – Android 16；iOS 13+ | 设备矩阵 |
| NFR-07 | 隐私 | 全部数据本地存储；无网络权限申请（v1 不引入网络依赖） | Manifest 审计 |
| NFR-08 | 可维护性 | flutter analyze 0 error / 0 warning；单测覆盖调度引擎 ≥ 90% | CI 门禁 |
| NFR-09 | 可用性 | 六页信息架构 + 任务创建 ≤ 90s 完成引导 | 可用性走查 |
| NFR-10 | 安全 | 取证文件位于应用私有目录；`*.evidence.*` 永不入版本库 | .gitignore + 代码审计 |

## 3. 约束

1. **平台约束**：iOS 无系统级常驻方案，被杀后仅通知兜底（用户预期管理）。
2. **政策约束**：`USE_EXACT_ALARM` 仅闹钟/日历类应用可在 Play 上架使用；
   本应用默认走 `SCHEDULE_EXACT_ALARM` 用户授权流（见 docs/08 §5）。
3. **合规约束**：免打扰护栏、冷却下限、音量上限为硬编码，配置不可绕过。
4. **网络**：v1 不申请 INTERNET 权限（最大化隐私）；
   v2 云备份功能将作为显式可选模块评审后加入。

## 4. 范围外（Out of Scope）

- 云端同步/多设备管理（v2+）
- 他人声纹识别、定向追踪（**永久 Out of Scope，违反产品红线**）
- 电话/短信类自动化动作
- iOS 小组件 / Watch 扩展（v2 评估）
