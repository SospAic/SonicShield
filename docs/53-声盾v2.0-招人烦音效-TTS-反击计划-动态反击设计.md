# 声盾 v2.0 模块设计：招人烦音效库 · 仿真 TTS · JSON 随机反击计划 · 实时动态反击

> 本文对应第七十六轮交付的四簇能力，覆盖设计取舍、数据契约、接线与失效安全。
> 实现入口与回归锁见文末「关键文件」与「回归锁」两节。

## 0. 总览与共同约束

四簇能力共享三条**贯穿性约束**（用户明确要求，也是本设计的第一原则）：

1. **本机与远程同源** —— 同一条业务通路（同一 materializer / 同一 `TtsService` / 同一
   `PlaybackService`），本机 UI、文件导入、远程 `plan.apply` **不各写一套**。
2. **不与手动内容冲突、不崩溃** —— 反击计划任务使用独立命名空间 `counter:{planId}:`，
   与 UUID 手动任务**结构上不可能碰撞**；所有播放经统一互斥（`PlaybackService.anyPlaying`）。
3. **失败要可见，不静默** —— 未配置 Key / 网络失败 / 音源缺失 / 校验不过，一律**如实回报**，
   绝不假成功、绝不悄悄降级成"看起来好了"。

## 1. 招人烦音效库（`annoy` 分类）

- **生成**：`tool/gen_sfx.dart` 新增 `annoy` 分类（10 条：连咳、清嗓加剧、吐痰、嘲笑、
  讥笑、喝倒彩、咂嘴、「干啥呢」、拖长抱怨、「哎呦」），复用既有程序化合成器
  （`bandpass` / `attackDecayEnv` / `formantVoice`）。运行生成器重建
  `assets/audio/presets/annoy_*.wav` 与 `presets_manifest.json`（**60→70 条 / 12→13 分类**）。
- **导入**：`lib/features/sounds/sound_library_screen.dart` 的预置导入把 manifest 的
  **稳定 id**（如 `annoy_spit`）写进音源行的**第三个 tag** —— 这是反击计划回查
  "本机装了哪些计划点名音效"的唯一依据（资产行 id 是导入时生成的 UUID，无法反推）。
- **逼真度边界**：程序化合成有上限；**保留真人录音导入**路径（`FilePicker`），版权由用户自负。

## 2. 仿真 TTS（双模：离线系统 TTS + 可选在线音色）

- **音色目录** `lib/domain/models/tts_voice.dart`：`TtsVoice{id,name,gender,dialect,provider,systemMatch,onlineVoiceId}`；
  普通话男/女多条 + **东北话**（小北女 / 云彪男），`TtsDialect` 分组。缺省 `''` = 系统自动挑。
- **统一入口** `lib/services/tts_service.dart`：`say(text,{voiceId,volume})` 按音色决定走
  `system`（flutter_tts，按 `systemMatch` 选音色）或 `online`（Azure 兼容 REST → 临时文件 →
  `PlaybackService.play`）。**空文本 / 在线未发声 / 委托抛错 ⇒ 失败结果**（异常不外泄）。
- **全链路接线**：`TtsAction.voiceId`（`lib/domain/models/action.dart`）→
  本地定时（`background_engine.dart`）、本机试听（`settings_screen.dart`）、
  远程脚本步骤 `tts {text,volume,voiceId?}`（`rc_script.dart` → `endpoint_service` 的
  `ttsHandler(text, volume, voiceId:)` → `main.dart` 的 `ttsHandler`）**全部走同一 `TtsService`**。
- **在线配置**：`lib/data/repositories/api_config_store.dart` 的 `ttsEndpoint` + `ttsApiKey`；
  未配置 ⇒ `onlineTtsConfigured == false` ⇒ 相关音色如实报"未发声"。

## 3. JSON 随机反击计划（固定 schema，100% 可导入）

### 3.1 固定模版（唯一真源）

`lib/domain/models/counter_plan.dart` 定义 **`schema = sonicshield.counterPlan/1`**，
`fromJson` 容错（脏类型回落默认、越界值夹紧），`validate()→List<String>` 前置校验。
模版下载文件名 `sonicshield_counter_plan_template.json`（`CounterPlan.defaults().toPrettyJson()`）。

```json
{
  "schema": "sonicshield.counterPlan/1",
  "name": "…", "version": 1,
  "dayStartHour": 8, "dayEndHour": 20, "cooldownSec": 900,
  "workday": { "day":  { "enabled": true, "volumeMin": 0.5, "volumeMax": 0.8,
                          "durationSecMin": 3, "durationSecMax": 8, "actionsPerHour": 2 },
               "night":{ "enabled": true, "volumeMin": 0.3, "volumeMax": 0.5,
                          "durationSecMin": 3, "durationSecMax": 5, "actionsPerHour": 1 } },
  "restday": { "day":  { "enabled": false, "volumeMin": 0.5, "volumeMax": 0.8, … },
               "night":{ "enabled": false, "volumeMin": 0.1, "volumeMax": 0.3, … } },
  "presetIds": ["annoy_spit"], "ttsTexts": ["干啥呢？"], "voiceId": ""
}
```

**区间约定（与用户口径逐位一致）**：工作日白天 50–80% / 3–8s；工作日夜间 30–50% / 3–5s；
休息日白天 50–80% / 3–8s（**可选**）；休息日夜间 10–30% / 3–5s（**可选**）；
休息日两段默认关闭。

### 3.2 工作日 / 休息日基准

`lib/domain/scheduling/china_holidays.dart`：内置 2025–2026 法定放假 + **调休补班**表，
纯函数 `ChinaHolidays.dayKind(DateTime,{overrides}) → workday|restday`；
表外年份按星期六日=休息日、周一至五=工作日；`overrides`（手工/远程）优先于内置表。

### 3.3 物化与落库

- `lib/domain/scheduling/counter_plan_materializer.dart`：纯函数展开为**未来 N 天固定时刻**任务，
  id = `counter:{planId}:{yyyyMMdd}{D|N}{nn}`（`safePlanId` 归一化分隔符）。
- `lib/services/counter_plan_service.dart`：**校验 → 物化 → 落库 → 重算**的唯一编排。
  - `apply(replace:true)`（用户显式操作）= 先按命名空间**整族删除**再重建（防幽灵计划）；
  - `apply(replace:false)`（自动续算）= 只 `upsertMany`**不删除**，幂等；
  - 只用"先 UPDATE 再 INSERT"的 `upsertMany`（**无 DELETE** 的手动改写路径）⇒ 不触发
    `occurrences` 级联删除；**绝不触碰手动任务**。
  - `refreshIfNeeded`：已排 horizon 不足时无删除续排，防计划几天后静默停掉。

### 3.4 一键 AI 生成（DeepSeek，token 最省 + 100% 可导入）

`lib/services/deepseek_service.dart`：
- 提示词**最小化**：内联 schema 摘要 + 区间约束 + 动作白名单（`_allowedPresets`），
  `response_format={"type":"json_object"}`、低 `temperature`；
- 返回后 **严格 `CounterPlan.fromJson` + `validate()`**；失败**回灌错误做一次修复重试**，
  仍失败 ⇒ 如实失败（不假成功）；
- 汇总 `usage` token，供"最省"核验。

### 3.5 本机随机生成

`lib/domain/scheduling/counter_plan_random.dart`：**不调 AI**，按**同一区间约束**生成合规
`CounterPlan`（同 schema，可导出/导入/远程下发）—— 与 AI 生成**同构**，离线可用。

### 3.6 配置与分发

- 配置模块 `lib/data/repositories/api_config_store.dart`：默认
  `baseUrl=https://api.deepseek.com`、`model=deepseek-chat`，并带**内置默认 Key**
  （`ApiConfigStore.defaultApiKey`，出厂即开箱可用）。该默认**不是写死的唯一来源**：
  编译期可用 `--dart-define=DEEPSEEK_API_KEY=...` 覆盖，运行期可在设置页随时改写；
  **从未配置**回落内置默认、**显式保存空串**即停用（如实回到无 Key）。
  `clearAll` 后基址/模型/Key 各自回到内置默认、在线语音回到关闭。
  Key 处于停用态时 ⇒ 相关按钮**如实报失败、不发请求**。
- 模版下载：`Share.shareXFiles` 分发（可跨软件发送到本机）；
  导入：`FilePicker`（`FileType.any`）→ `CounterPlan.tryParse` → `validate` → `apply`。

### 3.7 远程命令

`lib/remote/protocol.dart` 新增 `plan.apply` / `plan.get` / `plan.stop`；
`endpoint_service` 落**同一** `CounterPlanService`；控制器 `controller_service` 提供发送方法；
权限复用 `RcPermGate`：`plan.get` = 只读（免授权），`plan.apply`/`plan.stop` = `script` 位；
回执走 `_ack`（`plan.get` 回 `RcEvt.plan` 快照）。

## 4. 实时随机动态反击

### 4.1 分级（`SoundGuardService`）

新增 `enum SoundGrade{light,medium,heavy}` 与 `SoundGradeLimits`
（heavyDb=-12 / heavySoftDb=-20/heavyMs=3000；mediumDb=-25 / mediumSoftDb=-30/mediumMs=2000），
纯函数 `gradeOf(peakDb,durationMs)`；`SoundEvent.grade` getter（**构造签名未变**，向后兼容）。

### 4.2 决策（`ReactiveCounterService`）

消费守卫的**同一条声音事件流**（**不额外采音**，复用守卫麦克风通路）：

- **有声音尽量记录**：内存全量 `record`；**落库审计只在 `counter` 决策时**触发
  （`audit` 过滤 `action != 'counter'`），避免 7×24 日志洪水。
- **轻量忽略、重量随机反击**：从动作池（音效 + TTS）随机挑，随机音量/时长；
  heavy 段 0.5–0.8/3000–8000ms，silence 段 0.3–0.5/2000–5000ms。
- **静默动态反制**：`silenceRangeFor` 在 **15–25 分钟**随机取阈，超时触发一次反制。
- **互斥 + 冷却 + 渐进升级**：`CounterBusyFn`（复用 `PlaybackService.anyPlaying`）为真 ⇒ 跳过；
  冷却 120s；升级到 `maxEscalation=4` 封顶。`CounterTimer` 为注入缝（宿主可测）。

### 4.3 接线与失效安全

- 装配/撤下：`background_engine.dart` 在**守卫成功启动**时才建 `ReactiveCounterService`
  （唯一声音来源）；守卫关 / 引擎停 ⇒ 撤下；`reactive` 通道支持热切换（prefs 决定）。
- UI：守卫页「动态反击」开关 → `BackgroundServiceManager.setReactiveCounter` → 引擎通道；
  **守卫未开**时打开该开关会弹提示「需要守卫运行才能听到声音」——避免"开了却静默无效"。
