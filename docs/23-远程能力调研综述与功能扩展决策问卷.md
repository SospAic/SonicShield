## §1 · 摸底综述

### 1.1 规模总览

| 维度 | 数量 | 说明 |
|---|---|---|
| 远程命令 | **27** | 控制端 → 端点 |
| 事件 / 回执 | **18** | 端点 → 控制端 |
| 指令组步骤 | **6** | `play` / `tts` / `record` / `vibrate` / `delay` / `notify` |
| 协助会话握手 | **5** | 独立命名空间 `assist.*` |
| 权限位 | **8** | 协助模式下逐位授权，默认全拒 |
| 传输 | MQTT over **TLS 8883** | 证书链强校验、fail-closed、无忽略证书开关（C-13 已闭环） |
| 内容加密 | HKDF-SHA256 → AES-256-GCM | topic 作 AAD，90s 重放窗，msg-id 去重 |
| 门禁基线 | 功能层 **1717** / 压测 24 / 可测面 **83.13%（7949/9562）**（全局 79.10%） | 最近一次全绿门禁（2026-09-27 第三十七轮，产物 `_pt/l10.txt`）实测；本文产出时为 1393 / 24 / 74.73%（当轮历史值） |

### 1.2 远程真能操控到的（全部经三向核对 + 回归锁）

- **出声**：`sound.play`（点名音源/分类/随机）、`ptt.voice`（对讲播放）、指令组 `play`/`tts`（喊话）。
- **音量**（🆕 本次升级）：`volume.set` 从"单个写死 80% 按钮"升级为**滑杆 + 5 档快捷位（静音/25/50/75/100）+
  按端点持久化回填 + 控制端钳制**（仅 Android；iOS 恒失败，面板明示）。
- **振动**：指令组 `vibrate`（固定节奏 + 参数化随机/持续）、`vibrate.stop`。
- **录音取证**：指令组 `record`（可被「终止执行」打断，停不下来会如实报错）。
- **任务自动化全量改写**：`task.list/toggle/skipNext/upsert/delete/runNow`。
- **设备快照**：`status.get`、`device.status`（电量/充电/版本）。
- **通话**：WebRTC 音视频 + MQTT 信令（`call.invite/answer/candidate/end`）。
- **守卫**：`guard.set`（前提：端点引擎已在跑）。
- **定位回传**：`location.get`（**前台**可用；后台如实报错，见 Q4）。
- **只读查询**：`ping`、`logs.recent`、`asset.list`、`preset.list`。
- **配对**：扫码双向握手 `pair.request`。

### 1.3 当前不可用（诚实清单）

| 能力 | 状态 | 原因 |
|---|---|---|
| `camera.snap` 拍照 | 硬禁用，恒回失败 | camera 插件与 AGP9 不兼容（docs/16 §9） |
| iOS `volume.set` | 恒失败（I-4） | 原生未实现；面板已明示 |
| 远程开引擎 / 弹权限窗 | 不可能 | 设计边界：远程不能替端点授权 |
| 后台定位 | Android 14+ 拒（C-1b） | FGS 类型位无 `location`、无后台权限 —— **现状是诚实失败** |
| `task.get` 单条拉取 | 有实现无入口 | 非必须 |

### 1.4 安全现状与已登记风险（决策问卷的背景）

| 项 | 现状 | 行业对标 |
|---|---|---|
| 配对码熵 | **39.26 bit**、KDF 快速派生 + **确定性公开盐**（W6 实测）⇒ GPU 分钟级可穷举 | 主流配对方案 ≥128 bit（ Matter / AirDrop PSKE） |
| Broker | 公共匿名服务，无鉴权/ACL（T-2）；TLS 只防窃听与篡改 | 企业 MDM 全部走自有通道 + 凭据 |
| 离线命令 | 仅 MQTT outbox（上线补发） | 全部主流方案用系统推送兜底 |
| 危险命令 | 无二次确认 | MDM「批准式操作」、adb 确认模式 |
| 权限闸 D-7 | `record` 位已由 `requiredPermBitsForTaskAction` 收紧（本次闭环主路径）；`runNow/toggle` 触发**既有**录音任务的残余面待端点服务侧接线 | 最小权限原则 |
| 审计 | 本地审计日志，可 `logs.recent` 拉取 | 等保/企业审计要求防篡改+可导出 |

### 1.5 平台差异（最容易漏的一栏）

| 能力 | Android | iOS |
|---|---|---|
| 全部命令 | ✅（除硬禁用的 `camera.snap`） | **iOS 目前是"能编译的桩"**（W1：部署目标 15.0 < `mobile_scanner` 要求 15.5.0、无签名团队、`native_bridge` 无 ios/ 目录） |
| 音量 | ✅ | ❌（恒失败，UI 明示） |
| 后台执行 | 前台服务 + 精确闹钟 | 不适用 |

**结论（W1）：在 I-3/I-4 收口前，任何材料不得声称支持 iOS。**

### Q1 · 配对码与密钥强度（T-1，安全 P0）

背景：配对码仅 39.26 bit，KDF 快速派生且盐公开可预计算 ⇒ 攻击者拿到一条密文就能离线穷举。
行业对标：Matter 通行证（ QR 含 280bit 随机数）、AirDrop（PSKE）、蓝牙配对（SC passkey ≥128bit）。

- A. 维持现状，仅在 UI/文档明示风险（小 / 低）
- B. **慢 KDF + 每设备随机盐 + 配对码轮换入口**（中 / 低，不破坏已配对设备）
- C. 配对码扩到 **≥128 bit + 协议版本 +1**（中 / **破坏性：全员重新配对**）
- D. B + C 组合，分两步走（中-大 / 低-中）

✅ ~~**推荐 D**~~（历史推荐）：先 B 止血（不破坏兼容），下个版本窗口做 C。

🧑 **用户裁决：B**（**与推荐不同** —— 只做 B 止血，**不做 C** 的 ≥128bit 破坏性扩码）。

### Q2 · Broker 治理（T-2）

背景：默认公共匿名 broker，谁都能连；TLS 不解决"谁有资格发"。
行业对标：企业 MDM 全部自有端点；HomeKit 直连 + iCloud 中继凭据。

- A. 维持公共 broker，文档明示（小 / 低）
- B. **支持用户自带 broker**（host/port/用户名/密码/TLS 全配置化，默认仍公共）（中 / 低）
- C. 默认改为**必须填私有 broker** 才能启用远程（中 / 中：抬高了使用门槛）

✅ **推荐 B**，并给公共模式加"演示用途"水印提示。

🧑 **用户裁决：B**（与推荐一致）。

### Q3 · 离线命令可达性（推送兜底）

背景：现在端点离线时命令只能进 outbox，端点重新连上 MQTT 才补发 —— 端点杀掉 App 或断网，命令就到不了。
行业对标：Find My / Family Link / 全部 MDM 都用系统推送（FCM / 厂商推送）做"拉起"。

- A. 维持 outbox（小 / 低）
- B. **+ FCM 数据消息**（端点收到推送拉起服务 → 连 MQTT 拉命令）（中 / 中：需 Firebase 项目与国内可达性评估）
- C. B + **厂商通道**（小米/华为/荣耀等，国内可靠性最佳）（大 / 中：多平台接入）

✅ ~~**推荐 B 先行**~~（历史推荐），C 列入路线图。

🧑 **用户裁决：C**（**与推荐不同** —— 直接做 B + 厂商通道）。决策出处 = `docs/24`（标题即 **Q3.C**）。

### Q4 · 后台定位（C-1b）

背景：Android 14+ 前台服务无 `location` 类型位、未声明后台权限 ⇒ 后台收到 `location.get` 如实报错。
行业对标：Family Link / Qustodio 均以"始终允许"定位 + Play 申报为前提。

- A. 不做，维持"诚实失败"（小 / 零风险）
- B. **做**：FGS 加 `location` 类型位 + `ACCESS_BACKGROUND_LOCATION` + 运行时"始终允许"引导 + Play 申报（中 / **中：政策申报 + 上架风险**）
- C. 折中：仅"端点前台或屏亮时"可用 + 明确引导（小-中 / 低）

✅ **推荐 A 现状 + C 的引导文案**；除非"找回/守护"场景被定为产品核心，再上 B。

🧑 **用户裁决：推荐**（= A 现状 + C 的引导文案；**C-1b 后台定位维持不做**）。

### Q5 · 危险命令二次确认与白名单

背景：`task.delete`、`vibrate.stop`、未来可能的锁定/抹除类命令目前直接执行。
行业对标：Intune/MDM 的"批准式操作"、adb 的确认模式、智能家居的"高危动作二次确认"。

- A. 全部直接执行（现状）
- B. **高危命令端点侧弹窗确认**（超时视为拒绝），高危清单写死在协议（中 / 低）
- C. B + **确认策略可配置**（每次确认 / 仅一次 / 免确认）（中-大 / 低-中）

✅ ~~**推荐 B**~~（历史推荐）；C 在多端点管理出现后再做。

🧑 **用户裁决：A**（**与推荐不同** —— 全部直接执行，**不做**危险命令二次确认）。

### Q6 · 多设备编排（设备组与策略引擎）

背景：现在控制台一次只能面对一台端点；任务/指令组都是单设备的。
行业对标：HomeKit 自动化（条件触发）、MDM 设备组、智能家居场景引擎。

- A. 维持单设备（小 / 零）
- B. **设备组 + 群发命令**（把指令组/命令广播给组内全部端点，逐台回执汇总）（中 / 中）
- C. B + **策略引擎**（"22:00 后进 A 组自动执行 X 指令组"）（大 / 中）

✅ **推荐 B**；C 是方向但建议等任务模型稳定。

🧑 **用户裁决：B**（与推荐一致）。

### Q7 · 远程屏幕能力（截屏 / 投屏）

背景：目前远程看不到端点屏幕，排障靠 `logs.recent` 文字。
行业对标：TeamViewer QuickSupport（单帧/受控投屏）、企业 MDM 远程查看（强制+审计）。

- A. 不做（小 / 零）
- B. **单帧截屏**（MediaProjection 单次授权截一帧回传，用户可见指示）（中 / 中：隐私敏感）
- C. 受控实时投屏（大 / 高：隐私 + 性能 + 政策）

✅ ~~**推荐 A 暂不做**~~（历史推荐）；排障先增强 `logs.recent`（结构化字段）。若做，必须是**端点用户可见、可拒**的形态（B 而非 C）。

🧑 **用户裁决：C**（**与推荐不同** —— 做**受控实时投屏**；红线要求"端点用户显式授权 + 全程可见指示"）。决策出处 = `docs/24`（标题即 **Q7.C**）。

### Q8 · 审计与取证增强

背景：审计日志已覆盖关键动作，但只在本机、只能拉最近若干条。
行业对标：等保/企业合规要求审计**可导出、防篡改、时间线可视**。

- A. 维持现状（小 / 零）
- B. **审计时间线 UI + 导出（CSV/JSON）+ 按命令类型过滤**（中 / 低）
- C. B + **哈希链防篡改**（每条审计含前条哈希）（中 / 低）

✅ ~~**推荐 C**~~（历史推荐；哈希链成本低、与"取证"定位契合）；导出格式按 docs/08 红线脱敏。

🧑 **用户裁决：A**（**与推荐不同** —— 维持现状，**不做**审计增强）。

### Q9 · 设备安全动作（找回 / 锁定 / 抹除）

背景：产品定位含"自我保护/守护"，但没有远程安全动作。
行业对标：Find My Device（响铃/锁定/抹除）、企业 MDM 的熔断。

- A. 不做（小 / 零）
- B. **响铃（已有）+ 全音量最大播放 + 锁屏提示消息**（中 / 低-中）
- C. B + **远程锁定/抹除**（大 / **高：法律与误触风险，必须二次确认 + 白名单**）

✅ **推荐 B**；C 需要法务评估与 Q5 的确认机制先行。

🧑 **用户裁决：B**（与推荐一致；注意 Q5 用户选了 A，故 C 的"确认机制前置"条件不成立，C 维持不做）。

### Q10 · 命令优先级 / 限流 / 配额

背景：命令 FIFO 处理；无频率限制（理论上可被刷屏）。
行业对标：QoS 优先级、API rate limiting、推送厂商的频控。

- A. 维持 FIFO（小 / 零）
- B. **优先级队列**（`vibrate.stop` / `script.stop` / 通话信令恒最高，可打断排队的录音/播放）（中 / 中）
- C. B + **限流与配额告警**（每端点每分钟 N 条，超限拒并审计）（中 / 低）

✅ **推荐 C**："停"类命令永远能插队"做"类命令，是安全底线；限流防滥用。

🧑 **用户裁决：C**（与推荐一致）。
